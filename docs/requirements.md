## 二、技术选型

### 2.1 最终选型

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面外壳 | **Electron** | Xmind 官方客户端本身就是 Electron，行为最贴近对标目标；Windows 生态成熟，文件对话框/打印/PDF 能力齐全 |
| 前端框架 | **React 18 + TypeScript** | 生态最全，复杂画布交互的组件化与类型安全 |
| 构建工具 | **Vite**（+ electron-vite） | 秒级热更新，开发体验最佳 |
| 状态管理 | **Zustand + Immer** | 轻量、无模板代码，适合画布高频操作；Immer 天然支撑撤销重做快照 |
| 渲染方案 | **混合渲染：节点用 DOM（HTML）+ 连线/边界/概要/装饰用 SVG** | 富文本、KaTeX 公式、图片、附件预览全部走原生浏览器能力，开发效率与保真度最高；配合视口裁剪满足 2000 节点 |
| 富文本引擎 | **TipTap（ProseMirror 内核）** | 成熟稳定的结构化富文本，可自定义「公式 / 图片 / 附件」内联节点类型 |
| 公式渲染 | **KaTeX** | 渲染快、体积小、支持导出矢量 |
| 布局引擎 | **自研**（9 种结构的布局算法模块化） | 无现成库能满足"全部结构 + 自由定位"要求 |
| `.xmind` 读写 | **JSZip + 自研序列化器** | `.xmind` = ZIP + `content.json` / `metadata.json` / `manifest.json` + `resources/` |
| 导出 | SVG 用自研**矢量导出器**；PNG 用 Canvas 栅格化；PDF 用 **pdf-lib** | 三种格式共用同一套布局数据，保证一致 |
| 打包 | **electron-builder** → NSIS + portable | 一次配置产出安装版与绿色版 |
| 图标 | lucide-react | 风格统一、Tree-shaking 友好 |
| AI | 原生 `fetch` 调 OpenAI 兼容 `/v1/chat/completions` | 零依赖，用户可自由换服务商 |

> 备选说明：Tauri + Rust 可把安装包从 ~150MB 压到 ~10MB，但需额外 Rust 工具链、PDF/导出类生态较弱，且与 Xmind 的技术血统不一致。如你更在意体积，可在确认时提出改用 Tauri。

### 2.2 渲染方案的取舍（重要，请知悉）

- **为什么不用纯 Canvas**：完整富文本 + 内联公式 + 内联图片需要自研文本排版引擎（断行、行内样式、行内对象混排），工作量大且难维护。
- **为什么不用纯 SVG**：2000 节点的富文本会产生大量 `<tspan>`，导出与编辑都受限（`foreignObject` 栅格化不可靠）。
- **结论**：DOM 渲染节点 + SVG 渲染连线，是本需求下**质量/工期最优解**；导出时由专用导出器把同一份布局数据重新输出为纯矢量 SVG。

### 3.1 核心数据模型（概要）

```ts
Workbook  { sheets: Sheet[], activeSheetId, metadata }
Sheet     { id, title, rootTopic: Topic, theme, relationships[], boundaries[], summaries[] }
Topic     {
  id, title: RichText,            // 富文本（结构化文档）
  children: Topic[],              // 附加子主题
  structureClass,                 // 该分支的结构类型
  markers[], labels[],            // 标记图标 / 标签
  notes: RichText,                // 备注
  hyperlink?, image?, formula?, attachments[],
  style?, collapsed, position?,   // 样式 / 折叠 / 自由定位
  extensions                      // 未知字段原样保留（兼容性兜底）
}
Relationship { id, fromTopicId, toTopicId, title?, style? }
Boundary     { id, topicIds[], title?, style? }
Summary      { id, fromTopicId, toTopicId, title? }
Theme        { id, name, structureColors[], nodeStyles, lineStyles, background }
```

**兼容性原则**：模型保留 `extensions` 未知字段通道，读写 `.xmind` 时未识别元素原样透传，避免"另存后信息丢失"。

### 3.2 性能策略

- 视口裁剪：只渲染可视区 + 缓冲区内的节点
- 布局结果缓存：仅子树变更时局部重算
- 缩放用 CSS transform（GPU 合成），不做全量重排
- 富文本编辑器**按需挂载**：只有进入编辑态的节点才实例化编辑器
- 自动保存走增量写入，避免大文件卡顿
