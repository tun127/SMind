## 二、怎么验收

应用**已经启动并在运行中**。如需重新启动：

```powershell
cd d:/SMind
npm run dev
```

### 建议按这个顺序点一遍

1. **打通录入闭环**：双击「中心主题」改文字 → 按 `Enter`（**提交并退出编辑**）→ 再按一次 `Enter`（新建一个**同级**主题，光标已落在其中）→ 直接输入 → 按 `Tab`（应提交并新建它的**子**主题）→ 继续输入。
2. **中文输入法（重点）**：切到中文输入法，输入拼音后按 `Enter` 或空格选词，**必须只上屏、不退出编辑**；同一个输入框里连续输入多个词也不应被打断。
3. **多行与自适应**：编辑时按 `Shift+Enter` 换行，观察节点自动变高变宽。
4. **其他快捷键**：`F2` 编辑、`Delete` 删除、方向键移动选择、`Esc` 放弃本次修改；选中主题后**直接打字（含空格）即进入编辑**，折叠 / 展开改用 `Ctrl + /`；`Ctrl+Shift+L` 打开**视角锁定**，镜头会跟住选中的主题。
5. **视口跟随**：连续按 `Tab` 往深处建节点，新节点应自动滚动到可见范围内，不会「凭空消失」。
6. **拖动改父级**：把某个子主题拖到另一个主题上，观察虚线高亮后松手，父级改变。
7. **自由摆放**：把主题拖到空白处，位置固定；再点工具栏「恢复自动布局」按钮复位。
8. **平移缩放**：拖动空白处平移；`Ctrl + 滚轮` 以指针为中心缩放；点「适应画布」看全图。
9. **保存**：`Ctrl+S` 存成 `.xmind`；在状态栏点「在文件夹中显示」核对文件。
10. **打开样本**：`Ctrl+O` 打开 `samples/03-标签标记与关系线.xmind`，确认折叠、标签、备注、关系线等数据被正确读入。
11. **往返保真**：打开样本后再「另存为」，用 Xmind 打开导出的文件，确认结构与文字一致。
12. **撤销重做**：连续 `Ctrl+Z` / `Ctrl+Shift+Z`。
13. **崩溃恢复**：改几个字后**不保存**，直接从任务管理器结束 Electron 进程，重新 `npm run dev`，应弹出「发现未保存的内容」。
14. **关闭保护**：改几个字后点窗口关闭按钮，应弹出未保存确认框。

### 命令行自检

```powershell
cd d:/SMind
npm run typecheck   # TypeScript 全量类型检查
npm run verify      # .xmind 解析 → 序列化 → 再解析 往返一致性校验
```

`npm run verify` 当前结果：**5 个样本全部往返一致**。

## 四、环境相关的一次性修复

安装依赖时机器的 npm 源是 `registry.npmmirror.com`，但 Electron 的二进制默认从 GitHub Releases 下载，被网络阻断，导致启动报 `Error: Electron uninstall`。

已在项目根目录写入 `.npmrc`：

```
electron_mirror=https://npmmirror.com/mirrors/electron/
```

以后重装 `node_modules` 会自动走国内镜像，不会再次失败。

## 4.5、P2 第一步：富文本（本轮新增）

### 做了什么

| 能力          | 说明                                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------------------- |
| 富文本编辑器  | 节点内换成 TipTap 编辑器，支持加粗、倾斜、下划线、删除线、字号、文字颜色、左/中/右对齐、项目符号、多段落 |
| 格式工具栏    | 进入编辑态后自动出现在底部，实时反映光标处的格式                                                         |
| 逐字符排版    | 测量与断行改为「逐字符 + 样式感知」，同一行内可以混排不同字号/颜色，节点尺寸随内容自适应                 |
| 与 Xmind 兼容 | 纯文本写进 `title`（外部编辑器照常可读），格式另存在扩展字段里；**没有格式的节点不会产生任何冗余数据**   |
| 段内换行      | `Shift+Enter` 换行，内部按段落拆分，与行模型一致                                                         |

### 怎么验收

1. **格式栏出现**：双击任意主题，底部应出现格式工具栏；非编辑状态应自动消失。
2. **局部加粗**：在节点里只选中前两个字 → 点 `B` → 只有这两个字变粗，其余不变。
3. **字号混排**：选中一部分文字把字号改成 22，观察节点自动变高变宽，且**同一行内两种字号能正确对齐**。
4. **颜色**：选一段文字点色块，颜色立即生效；点橡皮擦恢复默认。
5. **对齐**：左/中/右各点一次，文字位置应变化，退出编辑后保持。
6. **项目符号**：点列表按钮，应出现圆点列表；再点一次取消。
7. **段内换行**：`Shift+Enter` 换行后，节点应变成两行且**仍是一个主题**（Tab/Enter 建的是新主题）。
8. **中文输入法**：切中文输入法连续输入多个词，必须不被打断。
9. **快捷键仍然有效**：编辑中按 `Tab` / `Enter` 应提交并新建子/同级主题。
10. **不产生冗余数据**：双击一个从未格式化过的主题 → 直接按 `Esc` → 另存为 `.xmind`。用解压工具看 `content.json`，该节点**不应出现** `titleRich` 相关内容。
11. **格式能存能开**：给节点加上颜色和加粗 → 保存 → 重新打开，格式应完整保留。
12. **与 Xmind 互通**：把上一步的文件用 Xmind 打开，文字应完整，格式会丢失（见下方限制说明）。

### 本步骤的已知限制

| 限制                                                  | 原因                                                                 | 计划                                                            |
| ----------------------------------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------- |
| 编辑态与退出编辑后的换行位置可能有 1–2 像素差异       | 编辑态用浏览器排版，退出后用 Canvas 逐字符测量，两者度量存在极小差异 | 可接受；若明显再对齐字体度量                                    |
| 用 Xmind 打开本软件保存的文件，**文字完整但格式丢失** | 格式存放在扩展字段里（这也保证了 Xmind 不会因为不认识的字段而报错）  | 已确认为有意取舍，待拿到真实 Xmind 文件后尝试对齐官方富文本格式 |
| 渲染层 JS 增大到 1.65 MB（TipTap 约占 870 KB）        | 富文本编辑器体积较大                                                 | P9 改为按需懒加载                                               |

## 4.6、P2 第二步：主题系统

### 做了什么

| 能力       | 说明                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------- |
| 内置主题库 | 6 套：默认蓝、极简白、森林、暖阳、深色、商务。一键切换，画布背景、网格、节点、连线配色整体变化 |
| 配色微调   | 画布背景、网格点、中心主题底色/文字、一级主题底色/文字、深层文字、连线粗细、连线浓淡，全部可调 |
| 分支配色   | 一级分支配色列表可增删改，按顺序循环使用，整个分支（描边 + 连线）一起变                        |
| 自定义主题 | 「保存为我的主题」，存在用户数据目录，可删除，可导入/导出 JSON                                 |
| 撤销友好   | 拖动调色这类高频改动会自动合并为一步撤销（1.5 秒窗口）                                         |
| 与文件同步 | 配色写进 `.xmind` 的 theme 命名空间键；Xmind 打开不报错，Xmind 自己那套主题结构也原样保留      |

### 怎么验收

1. **切换主题**：点工具栏调色板图标 → 打开主题面板 → 依次点「深色」「森林」，画布背景、节点与连线应整体变化。
2. **深色可读性**：切到「深色」后，深层节点的文字应是浅色且清晰。
3. **微调**：改「中心主题底色」，画布上的中心节点应立即变色。
4. **分支配色**：把第 1 个分支配色改成红色，对应那一整个分支的描边与连线应变红。
5. **增删配色**：点「+」加一个配色；点色块右上角小叉删一个。
6. **连线**：拖动「连线粗细」「连线浓淡」滑杆，连线立即变化。
7. **撤销合并**：连续拖动同一个调色板 5 次，按**一次** `Ctrl+Z` 应全部还原（不是撤 5 次）。
8. **保存为我的主题**：填名字 → 保存 → 出现在「我的主题」中，可点击应用、可删除。
9. **导入导出**：导出为 `.json` → 删除该主题 → 导入刚才的文件 → 应恢复可用。
10. **随文件保存**：切主题 → 保存 → 重新打开，配色应完整保留。
11. **与 Xmind 互通**：用 Xmind 打开上一步的文件，不应报错，文字与结构完整（配色会是 Xmind 自己的默认主题，原因见下）。
12. **恢复默认**：点面板底部「恢复默认」应回到默认蓝。

### 已知限制

| 限制                                     | 原因                                                                                                  | 计划                            |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------- |
| 用 Xmind 打开时看到的是 Xmind 自己的配色 | `.xmind` 的 theme 结构是 Xmind 私有的，无法凭猜复刻；我们只在其中附加自己的命名空间键，Xmind 会忽略它 | 拿到真实 Xmind 文件后再尝试对齐 |
| 主题只改颜色，不改字体                   | 字号按层级固定（中心 19 / 一级 15 / 深层 14），这样切换主题不会击穿文本测量缓存                       | 如确需按主题换字体，后续扩展    |

## 4.7、P3：全部 14 种结构

### 做了什么

布局引擎重构为「共享内核 + 各结构独立算法」，并补齐了此前降级渲染的 11 种结构。现在下拉框里的每一种结构都有真实布局。

| 结构                      | 算法要点                                                     |
| ------------------------- | ------------------------------------------------------------ |
| 思维导图（平衡）          | 按子树高度把一级分支贪心均分到左右两侧，曲线连接             |
| 思维导图（顺时针）        | 以中心为圆心放射展开，半径按「节点尺寸所需间距」自动外扩     |
| 逻辑图（向右 / 向左）     | 单侧垂直堆叠，曲线连接。**新建导图的默认结构**（见 4.21 节） |
| 树形图（向右 / 向左）     | 与逻辑图同构，改为正交折线连接                               |
| 组织架构图（向下 / 向上） | 子节点横向铺开并居中，折线母线连接，同层上沿齐平             |
| 鱼骨图                    | 主脊 + 斜向骨刺上下交替，更深层沿骨刺向外堆叠                |
| 时间轴（水平 / 垂直）     | 主轴 + 一级主题交替分布，连线直接从主轴连出                  |
| 括号图                    | 子节点整体右移，用 `{` 形括号把一组子节点括起来              |
| 树状表格                  | 每层固定一列，同层左边缘对齐，行按子树高度堆叠               |
| 矩阵图                    | 一级主题排成一行表头，各列内部逐行列出后代                   |

### 怎么验收

`npm run samples` 已生成 **14 个结构样本**，位于 `samples/06-*.xmind` ~ `samples/19-*.xmind`。逐个打开，重点检查三件事：

1. **有没有节点重叠**（这是最容易出问题的地方）
2. **连线是否连到该连的节点**（不能出现线悬空、连错边）
3. **整体观感是否像该结构**（比如鱼骨图要看得出「主脊 + 骨刺」，时间轴要看得出主轴）

另外可以试：**选中根主题 → 用工具栏「结构」下拉框逐个切换**，同一份内容在不同结构间切换，内容不应丢失或错位。

### 已知限制

| 限制                                         | 说明                                     | 计划               |
| -------------------------------------------- | ---------------------------------------- | ------------------ |
| 鱼骨图的骨刺是直线斜插，Xmind 的骨刺略带弧度 | 视觉细节差异                             | 可按反馈微调       |
| 放射状在「分支多 + 标题长」时会摊得很大      | 为保证不重叠做了保守外扩，宁可大也不重叠 | 可加入扇区权重优化 |
| 时间轴的主轴是纯直线，没有刻度与端点装饰     | 未做                                     | 可后续补充         |
| 括号图每层都留出括号空间，层级深时会偏宽     | 结构性取舍                               | 可按反馈调整间距   |

2. **加标记**：选中一个主题 → 点工具栏「标签」图标 → 在面板里点「优先级 3」「红旗」「进度 2/4」。节点上方应立刻出现**数字徽标 3、红旗图标、四分之一饼形**，节点同时变高。
3. **一行一个（重点）**：在「优先级」这一行里依次点 1 → 3 → 5 —— 节点上**始终只有一个**优先级徽标

7. **超链接**：填入 `https://www.example.com` → 失焦 → 点「打开」，应调起系统浏览器。
8. **尺寸联动（重点）**：给一个很长的主题加 3 个标记，节点应明显变高而不是图标被裁掉；标签多到一行放不下时应自动折到第二行。
9. **撤销**：加几个标记后按 `Ctrl+Z`，应逐个回退（每次点选是一步）。
10. **落盘**：加完标记/标签/备注/超链接后 `Ctrl+S`，重新打开，应全部保留；用 Xmind 打开该文件，标记与标签也应正常显示。

## 4.9、P4 第二批：关系线 / 边界 / 概要（画布级元素）

### 做了什么

| 元素   | 呈现                                                                                   | 创建方式                                     |
| ------ | -------------------------------------------------------------------------------------- | -------------------------------------------- |
| 关系线 | 从 A 的**边框**连到 B 的**边框**，向外鼓出的弧线 + 箭头 + 可编辑标题，画在节点**之上** | **工具栏「关系线」**（按 `Ctrl` 选两个主题） |
| 概要   | 覆盖区间的大括号 + 概要文字                                                            | **工具栏「概要」**（选若干同级主题）         |
| 边界   | 包住区间内主题**及其整棵子树**的圆角矩形，分支色调半透明填充 + 可编辑标题              | **工具栏「边界」**（选若干同级主题）         |

> 创建入口已从右侧面板移到**工具栏**（带文字标签，不再需要辨图标）；面板里保留列表，可改标题或删除。
> **关系线两端各有一个圆点手柄，拖到另一个主题上即可改接那一端**（拖动时显示虚线预览，目标主题会高亮）。

### 几个关键实现点

- **区间语义**：Xmind 用 `(主题1,主题2)` 表示一段区间。我按「同一父级下的**连续兄弟**」解析——**反向区间自动纠正顺序**（`(C,A)` 等价 `(A,C)`），**跨父级/异常区间退化成单个主题**，不会把不相关的节点框进来。
- **括号方向**：由「父节点 → 区间中心」的**主导轴**决定，所以向右的思维导图括号在右侧、组织架构图括号在下方，不需要为每种结构写特例。
- **悬空引用清理**：删除主题时会自动清掉指向它的关系线/边界/概要。只删掉区间**中间**的主题不影响该区间；删掉**端点**则视为区间失效并一并清理，避免留下看不见却还在文件里的元素。
- **文字可读性**：概要/关系线标题用「画布色描边」而不是加背景块，压到别的内容上也读得清，且不需要测量文字宽度。
- 三个元素**数据早就能读写不丢**，这一批补的是几何计算与渲染。

### 本轮自检发现并修掉的缺陷

| #   | 现象                                        | 根因                                                       |
| --- | ------------------------------------------- | ---------------------------------------------------------- |
| 1   | 朝左/朝上的概要，文字压在括号上             | 概要文字的锚点写死了「接在右侧」，没有跟着括号方向翻转     |
| 2   | 关系线弧线容易横穿画布中心、压到中心主题    | 外凸方向是固定取的一侧法线，没有判断哪一侧更空旷           |
| 3   | 把主题拖到新父级后，可能留下失效的边界/概要 | 只有「删除主题」会清理悬空元素，「移动主题」没有清理       |
| 4   | 工具栏按钮禁用时看不到原因提示              | HTML 规范下禁用元素不触发 `title`；已把提示挂到外层 `span` |
| 5   | 工具栏按钮变多后，窗口变窄会把按钮压扁      | 工具栏没有溢出策略；已改为横向滚动且分组不参与压缩         |

### 怎么验收

1. **打开 `samples/03-标签标记与关系线.xmind`**（最直观），应当同时看到三个元素：
   - 一条从「React」指向「后端」的**带箭头弧线**，曲线中点写着「需要配合」；
   - 一个包住「后端」与「设计」（含各自子节点）的**半透明圆角矩形**，左上角写着「后续推进」；
   - 一个大括号覆盖「React」与「TypeScript」，尖端外侧写着「优先攻克」。
2. **工具栏入口**：选中一个主题时，「关系线」按钮是灰的；把鼠标停在灰按钮上，**应能看到提示「请先按住 Ctrl 选中两个主题」**（禁用按钮的提示特意挂在外面那层）。
3. **自己造关系线**：点选主题 A → 按住 `Ctrl` 点主题 B → 工具栏「关系线」→ 画布上应出现带箭头的弧线，且**箭头正好落在 B 的边框上**。
4. **拖动改接（本轮新增，重点）**：关系线两端应有**小圆点**。按住一端的圆点拖动 → 应出现**虚线预览**，指到别的主题上时该主题**高亮** → 松手后连线改接到新主题。把一端拖到**已连着的那一端**应被拒绝（不会产生零长度连线）。
5. **自己造边界 / 概要**：按住 `Ctrl` 选中两个同级主题（含子节点）→ 工具栏「边界」→ 矩形应把两个主题**连同它们的子节点**一起框住；「概要」→ 应出现大括号 + 文字「概要」，文字在大括号尖端外侧。
6. **改标题**：在面板里给关系线/边界/概要的标题输入框改字，**点别处**生效（回车也可）。
7. **方向正确性（本轮修复）**：切到「组织架构图」结构，概要的大括号应出现在**下方**；切到「逻辑图（向左）」，大括号与文字应整体**镜像到左侧**，文字**不压在括号上**。
8. **删除清理**：给两个主题建好关系线与边界后，删除其中一个主题，关系线应立刻消失、边界也应消失，**画布上不应留下任何悬空的线或框**。
9. **撤销**：创建/删除/改接这些元素后 `Ctrl+Z` 应可逐步回退。
10. **落盘**：建好后 `Ctrl+S` 保存再打开，三者都应完整保留；用 Xmind 打开也应能正确显示。

| -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 概要/边界**参与布局空间预留**（已做，覆盖共享堆叠家族 + 组织架构行） | 以前边界标题带会压住上方分支、组织架构图里会压住中心主题（自检 8.5j 组用「关掉预留就变红」锁住）。现在把「边界/概要向外占用的量」与绘制共用同一批常量交给布局：竖直堆叠家族（思维导图各向 / 逻辑图 / 树形图 / 树状表格 / 括号图）按上/下留白，组织架构行按整行留白。**未覆盖**：鱼骨图、时间轴、放射图、矩阵行距（这些结构的覆盖层朝向各不相同，留待逐结构验证后接） |

## 4.10、P4 第三批：线身拖动 / 开关式创建 / 左键框选右键平移

### 1. 关系线的线身也能拖动了

| 操作               | 效果                                                                 |
| ------------------ | -------------------------------------------------------------------- |
| 拖动关系线**线身** | 整条弧线跟着移动（外凸幅度与标题一起变），连续拖动合并为**一步撤销** |
| **双击**线身       | 恢复到自动计算的弯度                                                 |
| 拖动**两端圆点**   | 把这一端改接到别的主题（上一批已实现）                               |

偏移量存放在 `relationship.style.properties` 的 `com.mindmap.local.curve` 键里——用样式属性而不是新增字段，是因为 Xmind 会忽略不认识的属性键，**文件仍能被 Xmind 正常打开**，我们的读写也不丢。**端点位置不受线身拖动影响**（拖线不会把连线拖离节点）。

### 2. 「关系线 / 概要 / 边界」改成开关

之前的实现里，对同一段选择连点「边界」会**重复叠加多个半透明矩形**，看起来就像「点一下颜色变深一点」。现在改成：

- **没加过 → 点击创建**（按钮正常样式）
- **已加过 → 按钮显示为「已按下」（蓝色高亮）**，再点一次即移除
- 反向选中同一对主题（先选 B 再 Ctrl 选 A）也视为同一条线/同一段区间

同时修掉了颜色叠加的根因：**同色的多个边界现在合并成一条 SVG path 一次性填充**，即使两个边界区域真的重叠，重叠处也不会被半透明叠加成更深的颜色。

### 3. 左键框选、右键平移（Xmind 同款）

| 操作                   | 行为                                             |
| ---------------------- | ------------------------------------------------ |
| **左键拖动空白处**     | 框选：显示蓝色虚线橡皮筋，松手后选中框内所有主题 |
| 左键拖动 + `Ctrl`      | 追加选择（不清掉之前选中的）                     |
| 左键点一下空白处       | 取消选择                                         |
| **右键（或中键）拖动** | 平移画布（已屏蔽系统右键菜单）                   |
| `Ctrl + 滚轮`          | 以指针为中心缩放（不变）                         |

### 本轮自检发现并修掉的缺陷

| #   | 现象                                                          | 根因                                                                                                                                                                    |
| --- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 启动后**界面卡死、控制台报「Maximum update depth exceeded」** | 我把「开关状态查询」函数直接当 zustand selector 用，它每次返回**新对象**，触发 `useSyncExternalStore` 无限重渲染。已改为纯函数 + `useMemo`，并新增 8 条断言锁住这个行为 |
| 2   | 快捷键说明里「编辑中 Enter = 确认并退出编辑」                 | 这是**第一轮反馈之前**的旧行为，说明一直没同步。已改为「确认并新建同级主题」，并补上「编辑中 Tab」「框选」「关系线拖动」等新增条目                                      |

### 怎么验收

1. **开关**：选两个主题 → 点「关系线」→ 画布出现弧线，**按钮变成蓝色高亮** → 再点一次 → 弧线消失、按钮还原。边界、概要同样验证。
2. **不再叠深**：选两个主题 → 连点 5 次「边界」→ 边界框应该只有**一个**，颜色深浅不变（以前会叠出 5 层越来越深）。
3. **拖线身**：抓住关系线**中间**拖动 → 弧线跟着走，两端**仍钉在原来的节点上**；`Ctrl+Z` 一次回到原位；**双击**线身复位。
4. **框选**：在空白处按住左键拖出一个框 → 松手后框内的主题**全部选中**（状态栏节点数变化）；按住 `Ctrl` 再框一块 → 是**追加**而不是替换。
5. **右键平移**：按住右键拖动 → 画布平移，**不弹系统右键菜单**。
6. **落盘**：拖动线身后 `Ctrl+S` → 重新打开，弧线位置保持；用 Xmind 打开也不报错。

## 4.11、缺陷修复：概要等内容无法修改

### 现象

概要（以及边界、关系线）的文字「改不动」。

### 定位过程

我没有凭猜测改，而是先补了一条上一轮**遗漏的自检用例**——`setSummaryTitle` / `setBoundaryTitle` 这两个动作之前竟然从未被直接测过。用例一跑，立刻暴露真缺陷：

```
✗ 清空概要标题后为空 —— 实际=undefined 期望=""
✗ 清空后画布上也不该冒出主题的文字 —— 实际="甲" 期望=""
```

### 两个原因

| #   | 原因                                   | 说明                                                                                                                                                                                                                                   |
| --- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **画布上没有编辑入口**                 | 面板里的输入框是能用的（改成非空文字的用例是通过的），但用户的自然反应是在画布上双击文字——而我们没实现，所以感觉「改不动」                                                                                                             |
| 2   | **清空文字后会冒出别的文字**（真缺陷） | 概要的文字有回退逻辑：自带标题为空时，显示 `topicId` 指向主题的文字（这是为了兼容真实 Xmind 文件——它们的概要文字往往挂在主题上）。但用户**主动清空**时，文字被存成 `undefined`，于是立刻回退显示成「甲」，看起来就像「删不掉、改不动」 |

### 修复

1. **双击画布上的标题即可就地编辑**（与节点文字编辑同一套体验）：
   - 概要文字、边界标题、关系线标题都支持双击编辑
   - 边界额外加了**透明命中区**，双击框内任意位置都能改标题（新建的边界默认没有标题，否则没有文字可点）
   - `Enter` 或点别处保存，`Esc` 放弃（已处理输入法组词，中文输入不会被打断）
2. **清空就是清空**：用户主动清空时写入空串而非 `undefined`，不再回退成主题的文字；同时保留「真实 Xmind 文件没有自带标题时回退到主题文字」的兼容逻辑（判断条件从「非空即真」改成 `!== undefined`）。

### 怎么验收

1. **双击改文字**：给两个同级主题加概要 → **双击画布上的「概要」两个字** → 输入「核心任务」→ 按 `Enter` → 文字应立刻变成「核心任务」。
2. **清空不回弹**：再双击 → 把文字全删掉 → `Enter` → 概要文字应当**消失且不冒出主题名字**（这是本次修复的重点）。
3. **边界同样可改**：新建边界（默认没标题）→ **双击边界框内任意位置** → 输入「后端部分」→ `Enter` → 左上角出现标题。
4. **关系线标题**：双击关系线中间的标题文字也能改。
5. **中文输入法**：编辑时切中文输入，选词用的回车不应提前提交。

## 4.14、P5：大纲模式

### 做了什么

| 内容         | 说明                                                                                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 大纲面板     | 工具栏上的「大纲」按钮打开左侧面板，与画布**并排**显示（画布自动让出左侧 320px）                                                                           |
| 双向实时同步 | 不是靠同步代码，而是两边**共用同一份 store**：大纲改了画布立刻变，画布改了（含改文字、加标记、折叠、拖动换父级）大纲立刻变，物理上不可能出现两份数据不一致 |
| 结构化编辑   | `Enter` 新建同级、`Tab` 降级（变成上一个同级主题的子主题）、`Shift+Tab` 升级、双击改文字、`空格` 折叠展开、`Delete` 删除、`↑/↓` 上下移动选择               |
| 状态提示     | 每行右侧用小图标标出「有标记 / 有标签 / 有备注 / 有链接 / 有附件 / 有图片 / 有公式」                                                                       |
| 折叠联动     | 大纲里折叠的分支会连子节点一起收起，与画布上的折叠是同一个状态                                                                                             |
| 浮动主题     | 自由摆放的浮动主题也会出现在大纲里（排在树的最末尾），不会「在大纲里消失」                                                                                 |
| 三种导出     | 面板右上角 `TXT` / `MD` / `OPML` 按钮，导出**当前画布**的大纲                                                                                              |

### 三种导出格式长什么样

以 `samples/21-Xmind8旧版格式.xmind` 为例（真实输出）：

```text
TXT：                    Markdown：                    OPML：
旧版文件 & 兼容测试       # 旧版文件 & 兼容测试          <?xml version="1.0" encoding="UTF-8"?>
  带标记与标签              <空行>                       <opml version="2.0">
  已折叠的分支              - 带标记与标签                  <head><title>画布 1</title></head>
    折叠里的子主题            > 这是一条备注……              <body>
  带图片与附件              - 已折叠的分支                    <outline text="旧版文件 &amp; 兼容测试">
  自带结构类型的子分支        - 折叠里的子主题                   <outline text="带标记与标签" _note="…" _link="…"/>
  三级主题                  - 带图片与附件                     <outline text="已折叠的分支">
  带未知元素的分支                                             <outline text="折叠里的子主题"/>
  浮动主题                                                     </outline>
                                                               </outline>
                                                             </body>
                                                           </opml>
```

细节约定：

- **TXT**：每行一个主题、按层级缩进两个空格，带 UTF-8 BOM（Windows 记事本 / Excel 打开中文不乱码）
- **Markdown**：根主题是一级标题，其余是列表；备注写成引用块
- **OPML**：根主题也画一层 `<outline>`，备注进 `_note`、超链接进 `_link`，可直接导入 Xmind / 幕布 / Workflowy；XML 特殊字符已转义
- **导出包含折叠分支里的内容**（导出是「把数据拿走」，不该被折叠状态挡住）
- 导出的是**当前画布**；文件默认名取画布标题

### 怎么验收

1. 点工具栏「大纲」→ 左侧出现大纲，画布右移。
2. **画布 → 大纲**：在画布上给某个主题加个标记、改个文字，大纲对应行立刻出现图标 / 文字变化。
3. **大纲 → 画布**：点大纲某行 → 画布上该节点高亮；双击改文字 → 画布上节点的文字同步变化。
4. **结构化编辑**：在最后一行按 `Enter` 生成同级，输入文字 → 按 `Tab` 降级（观察画布上它变成上一个主题的子级）→ 按 `Shift+Tab` 升回来。
5. **折叠联动**：在大纲里点箭头折叠某分支 → 画布上对应节点也折叠起来。
6. **导出**：点 `MD` → 保存 → 打开导出的文件，核对层级与备注；点 `OPML` 导出后用 Xmind 或幕布导入看看能否还原结构。
7. **中文输入法**：在大纲行里用中文输入法打字、选词回车，不应提前提交。

### 几个设计取舍（需要你知情）

- **替换只动标题**：备注与标签只参与搜索。原因是备注要同时维护「纯文本 + HTML」两份内容，改一份不改另一份会造成两者说法不一致（上一轮修过同类问题）。
- **被替换的标题会丢掉局部格式**：如果标题里有「某个词加粗/变色」，替换后文本长度变了，原格式区间就对不上，所以退化成纯文本（面板里有说明）。
- **切换画布不算「修改」**：不写撤销历史、不把文档标记为未保存；`activeSheetId` 会在下次保存时一并写进文件。

### 怎么验收

1. **搜索跳转**：`Ctrl+F` → 输入「设计」→ 结果列表出现若干条 → 点其中一条 → 画布上对应节点被橙色描边并居中。
2. **搜索范围**：勾上「包含备注」再搜一个只出现在备注里的词 → 应能搜到，且片段前面标着「备注」。
3. **替换**：搜索框里输「评审」→ 替换框输「检查」→ 点「全部替换」→ 提示替换了多少处 → 画布上文字变了 → `Ctrl+Z` 应能整体撤回。
4. **单条替换**：点某条结果右侧的箭头 → 只替换那一个节点。
5. **筛选**：在筛选区点「优先级 1」图标 → 只有带该标记的节点（及其祖先）正常显示，其余淡出 → 再点一次取消。
6. **筛选组合**：同时选「优先级 1」+ 某个标签 → 命中数量应变少（且关系）。
7. **统计**：打开 `samples/03-标签标记与关系线.xmind`，核对面板里的节点数、字数、标记分布、标签分布是否与实际相符。
8. **多画布**：打开 `samples/04-多画布工作簿.xmind` → 底部应有两个画布标签 → 点第二个应切过去 → 双击标签改名 → `+` 新建 → 在非最后一张上点 `×` 删除 → `Ctrl+Z` 撤回。

## 4.16、P6：导出 PNG / SVG / PDF

### 做了什么

| 内容 | 说明                                                                          |
| ---- | ----------------------------------------------------------------------------- |
| 入口 | 工具栏「导出」按钮 → 设置框里选格式 / 清晰度 / 背景 → 导出当前画布            |
| PNG  | 位图，1×–4× 清晰度可选，适合发群、贴文档                                      |
| SVG  | 矢量：文字是 `<text>`、连线与边界是 `<path>`、圆角与下划线是真实图元          |
| PDF  | 单页 PDF，页面尺寸按屏幕尺寸等比换算（`CSS 像素 × 0.75`），打印出来与屏幕一致 |
| 背景 | 跟随主题配色 / 纯白 / 透明（透明仅对 SVG 生效，位图会填白底）                 |
| 范围 | 导出**当前画布的全部内容**，不受折叠状态与筛选影响                            |

### 关键技术点

- **同一份布局数据**：导出走的是与画布完全相同的 `measureTopic` + `layoutSheet`，
  所以导出的排版就是你屏幕上看到的排版，不存在「导出后又排一次版」导致的偏差。
- **一份指令、两个后端**：布局先翻译成中立的绘图指令（`export/drawing.ts`，纯函数），
  再由 `svg.ts`（拼字符串）与 `raster.ts`（Canvas 2D）分别消费。
- **公式怎么进导出**：公式是 KaTeX 的 HTML，不是 SVG 图元。导出时用 `foreignObject`
  包一层、由浏览器栅格化成位图再嵌进结果；KaTeX 的 **CSS 与 20 个 woff2 字体在构建期已内联**
  成 `export/katex-assets.ts`（361 KB，**按需动态加载**，不导出公式就不加载）。
  任何一步失败都退化成「画 LaTeX 源码」，不会让整次导出失败。
- **PDF 零依赖**：PDF 的矢量能力需要用它自己的绘图 API 重写一遍排版，
  所以这里用自研的 PDF 写入器把高清位图打包成单页 PDF（含正确的 xref 偏移与 UTF-16BE 中文标题）。
- **超大画布自动降倍率**：超过 canvas 单边上限时自动降低倍率，避免导出直接失败。

### 怎么验收

1. **PNG**：打开 `samples/03-标签标记与关系线.xmind` → 工具栏「导出」→ 选 PNG、2×、跟随主题 → 导出 →
   用图片查看器打开，核对：节点文字、标签胶囊、标记图标、关系线箭头、边界与概要是否都在，
   且与屏幕一致。
2. **清晰度**：同样内容分别导出 1× 与 4×，后者应明显更清晰、文件更大。
3. **透明背景**：PNG 选「透明」导出 → 位图会是白底（说明里已注明透明只对 SVG 生效）；
   SVG 选「透明」导出 → 用浏览器打开，背景应是透明的。
4. **SVG 矢量性**：SVG 导出后用浏览器打开、按 `Ctrl+ +` 放大到很大 → 文字与连线**不应发虚**
   （文字是矢量；图片与公式是内嵌位图，放大到极致会看到它们先糊）。
5. **公式**：打开 `samples/20-图片公式附件.xmind` → 导出 PNG → 公式应与画布上一样是排好版的数学符号，
   而不是 `\sum` 这样的源码。
6. **PDF**：导出 PDF → 用阅读器打开 → 应是一页、内容完整、中文标题正常（不出现乱码）；
   打印预览里的尺寸应与屏幕上差不多大。
7. **中文与特殊字符**：把某个主题标题改成 `A & B <C>` 再导出 SVG → 用浏览器打开不应报 XML 错误。
8. **大图**：打开 `samples/19-结构-矩阵图.xmind` 导出 4× PNG，应能正常出图（不报「超出画布尺寸」）。

## 4.17、界面入口整理：常用功能全部放到工具栏

### 改动前的问题

## 4.18、P8：AI 功能

### 做了什么

| 功能             | 说明                                                                                                                       |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **一键生成导图** | 给一个主题（可选层级、补充要求）→ 生成整张导图；可**生成到新画布**，也可挂到**选中主题**下面                               |
| **扩写子主题**   | 选中一个主题 → 让 AI 补 N 个新的子主题（自动带上已有子主题与备注作为上下文，避免重复）                                     |
| **润色标题**     | 选中一个主题 → 改写它的文字，可指定风格                                                                                    |
| **AI 设置**      | BaseURL / 模型名 / API Key / 采样温度，内置 DeepSeek、OpenAI、通义、智谱、Kimi、本地 Ollama 的**一键预设**；带「测试连接」 |

### 关键设计

- **协议**：只用 OpenAI 兼容的 `/v1/chat/completions`，所以换服务商只需要改 BaseURL + 模型名；
  BaseURL 会被自动规整（填 `https://api.x.ai`、`…/v1`、`…/v1/` 都能用）。
- **网络请求在主进程**：① 绕开渲染进程的 CORS 限制；② 超时（默认 120 秒）与错误翻译集中一处；
  ③ **API Key 只存在本机的 `ai-config.json`**，不进渲染进程、不写进 `.xmind`，界面上只显示 `sk-…3f9c` 这样的掩码。
- **让模型输出缩进大纲而不是 JSON**：大纲用纯文本表达更稳，模型不容易写坏引号把整段作废。
  解析层做了容错：代码块包裹、`*`/`+` 列表、`1.` 数字列表、Markdown 标题、制表符缩进都能读；
  **模型常见的开场白（「好的，以下是……」）会被自动跳过**（这是自检抓出来的问题）；
  一行标记都没有时退化成「一行一个主题」，但只收短句，避免把整段解释文字变成节点。
- **结果先预览再应用**：对话框里显示解析出的树，确认后才写入画布。
- **整批算一步撤销**：无论生成多少个节点，都写进一次 `mutate`，不满意直接 `Ctrl+Z` 撤回。
- **只在点「生成」时联网**，其余功能全程离线。

### 怎么验收

1. **先配 Key**：工具栏 `AI ▾` → 「AI 设置…」→ 点一个预设（例如 DeepSeek）→ 填 API Key → 点「测试连接」→
   应提示「连接正常（模型 …）」；填错 Key 应提示「鉴权失败（401）：API Key 不对…」。
2. **一键生成**：`AI ▾` → 「一键生成导图…」→ 输入「如何在一个月内学会做菜」→ 层级 3 → 点「生成」→
   下方应出现解析出的树形预览 → 点「应用到画布」→ 新画布上出现整张导图；按 `Ctrl+Z` 应能整体撤回。
3. **挂到选中主题**：在画布上选中某主题 → 生成时把「生成到」改成「选中主题的子主题」→ 结果应挂到该主题下。
4. **扩写**：选中「市场分析」→ `AI ▾` → 「扩写子主题」→ 数量 5 → 生成 → 预览列出 5 条 → 应用后应出现在该主题下，
   且与已有子主题不重复。
5. **润色**：选中一个写得啰嗦的节点 → `AI ▾` → 「润色标题」→ 生成 → 预览显示润色结果 → 「替换标题」→
   画布上文字变化，`Ctrl+Z` 可撤回。
6. **错误提示要能看懂**：把 BaseURL 改成 `https://example.com` 再点测试 → 应给出「连不上 / 接口不存在」这类可读提示，
   而不是一串英文堆栈；把模型名改成不存在的东西 → 应提示可能是模型名不对。
7. **离线不联网**：不点 AI 的情况下，其它功能（编辑、保存、导入导出）不应有任何网络请求。

## 4.19、修复「AI 按钮点击无效」+ 缩短快捷栏

### 问题的真正原因（两个抱怨其实是一个）

工具栏以前是 `overflow-x: auto`（按钮多了就横向滚动）。按 CSS 规范，**只要一个方向是 auto，另一个方向的 visible 就会被算成 auto**——
于是工具栏变成了「裁切容器」，而下拉菜单是绝对定位在按钮下方的，**整个菜单被工具栏的下边缘裁掉了**。
点「AI」时代码其实跑到了（菜单确实"打开"了），只是你看不见它，所以表现为「点击无效」。导入▾ / 导出▾ 有同样的问题。

### 修复

| 改动                                         | 说明                                                                                                                                                    |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 下拉菜单改为**传送门（portal）+ fixed 定位** | 菜单渲染到 `document.body`，位置按按钮的 `getBoundingClientRect()` 计算，**不再受任何祖先容器的裁切影响**；下方空间不够时自动往上弹，超出可视高度可滚动 |
| 工具栏改为**换行**而不是横向滚动             | 窗口再窄也不会把按钮藏起来；同时去掉了那两条滚动条样式                                                                                                  |
| 点外部/按 Esc/滚动/改窗口大小都会收起菜单    | 点按钮自身也能收起（以前会自己弹回来）                                                                                                                  |

### 顺带缩短快捷栏

| 改动                                                                            | 省下的宽度 |
| ------------------------------------------------------------------------------- | ---------- |
| 「关系线 / 概要 / 边界」去掉文字，只留图标（提示语里写清用法）                  | 约 150px   |
| 「节点属性 / 主题外观 / 恢复自动布局 / 快捷键说明」收进最右的**「更多 ▾」**菜单 | 约 130px   |
| 「导入 ▾」新增 Markdown / OPML 两项，导入类功能集中一处                         | —          |

现在的工具栏（图标为主，导入导出 AI 保留文字便于发现）：

```
[新建][打开][保存][另存为] │ [撤销][重做] │ [加子主题][删除] │ 结构▾ │ [关系线][概要][边界] │
[大纲][搜索] │ [导入▾][导出▾][AI▾] ······ [缩小][100%][放大][适应画布] │ [更多▾]
```

### 怎么验收

1. **AI 能用**：点 `AI ▾` → 弹出菜单（应能看到「一键生成导图 / 扩写子主题 / 润色标题 / AI 设置」）→ 点任意一项应打开对应对话框。
2. **其它下拉同样可用**：`导入 ▾`、`导出 ▾` 都应正常弹出；菜单下方空间不足时应往上弹而不是被切掉。
3. **收起行为**：点击菜单外的任意位置、按 `Esc`、滚动画布，菜单都应收起；再点按钮也应能收起。
4. **窗口拉窄**：把窗口拖窄，工具栏应**换行**显示，所有按钮都还在（以前是横向滚动、按钮被藏）。
5. **「更多 ▾」**：应能打开节点属性、主题外观、恢复自动布局、快捷键说明。

## 4.20、导入 Markdown / OPML 一键生成导图

### 做了什么

| 入口                                  | 行为                                                                                  |
| ------------------------------------- | ------------------------------------------------------------------------------------- |
| `导入 ▾` → **导入 Markdown 生成导图** | 选 `.md` / `.markdown` / `.txt` → 按标题与列表自动生成一棵树 → **新建一张画布**放进去 |
| `导入 ▾` → **导入 OPML 生成导图**     | 选 `.opml` / `.xml` → 解析 `<outline>` 层级 → 新建画布                                |
| 原生菜单                              | 「文件 → 导入」子菜单里同样两项                                                       |

**Markdown 解析规则**：`#` 标题按级别嵌套；标题下的 `-` / `*` / `+` / `1.` 列表按缩进嵌套；
代码块（``` 包裹，含内容）、YAML front-matter、引用块、表格、水平线**一律跳过**（它们是说明不是结构）；
行内装饰会清理（`**粗**`→粗、`[文字](url)`→文字、`` `code` ``→code、`![图](a)`→图）；
普通段落不当节点——除非整篇一个标题/列表都没有，才退化成「一行一个主题（只收短句）」。

**OPML 解析规则**：读 `<outline text="…">` 的嵌套层级；`_note` **会被导入为节点的备注**（不丢数据）；
没有 `text` 的容器节点会把它下面的子节点提上来（而不是整段丢掉）；没有 `<body>` 也能兜底；
多个并列顶层节点会用文件标题套一个根。

**共同点**：导入结果整批写入**一次操作**，不满意 `Ctrl+Z` 一下撤回；导入到**新画布**，不动现有内容。

### 关于 .emmx（亿图脑图）—— 为什么这次没做直接读写

我拆了你给的 4 个 `.emmx` 样本，结论是**直接读写不可行**：

| 内容                                        | 情况                                                                                            |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `document.xml` / `theme.xml` / `rels/*.xml` | 是普通 XML，能读（但里面只有页面属性与配色）                                                    |
| **`mmpage/page.bin`（主题树就在这里）**     | **私有二进制**：标题是内嵌的 UTF-8 字符串，但父子层级、坐标都是二进制记录 + float，没有公开规范 |
| `mm.bkiwi`                                  | **加密/混淆过的二进制**，完全读不出结构                                                         |

逆向 `page.bin` 只能靠猜，而且**写回**（让亿图能打开）还需要完整私有 schema 与那套加密，
风险高、我无法可靠验证——做出来很可能是「看起来能用、实际悄悄丢结构」，这比不做更糟。

**替代路径（已经可用）**：亿图脑图自己可以导出 **Markdown / OPML / XMind**，而这三种我们现在都能导入：

- 亿图 → 导出 Markdown → 本软件「导入 Markdown 生成导图」
- 亿图 → 导出 OPML → 本软件「导入 OPML 生成导图」
- 亿图 → 导出 XMind(.xmind) → 本软件直接打开（已支持）

如果你确实需要直接读 `.emmx`，我可以用「尽力而为」的方式只把标题按顺序抽出来（**层级会不准、备注/标记会丢**），
但需要你先认可这个质量上限；要做得可靠，得靠更多样本慢慢逆向，投入产出比很低。

| 现象                                                   | 根因                                                                                                                                                                          |

## 4.13、版本快照：同一文档的历史版本

这补上了《需求确认书》里「自动保存 + 崩溃恢复 + 撤销历史」中的最后一项——**文件历史快照**。

### 做了什么

| 能力                   | 说明                                                                                                                        |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 手动版本               | 「存一个版本」按钮，可给版本写备注（备注会直接显示成列表标题）                                                              |
| 自动版本               | 每 **10 分钟**留一个；**内容与上一份相同就跳过**（比内容指纹），不会把盘写爆                                                |
| 恢复前兜底             | 每次恢复前**自动存一份「恢复前」的版本**，所以点错了还能切回来                                                              |
| 恢复                   | 走与「打开文件」**同一条通路**，图片与附件一并还原，不会出现「文字回来了图没了」                                            |
| 保留策略               | 单文档最多 30 个；**手动版本优先保留**，超限先裁自动版本（手动硬上限 50）                                                   |
| 只服务**已保存的文件** | 没有路径的文档不记录版本——需求原文就是「**文件**历史快照」；未保存内容由「每 30 秒自动存档 + 崩溃恢复」负责，两者职责不重叠 |
| 存储位置               | `%APPDATA%/<应用名>/snapshots/`（`index.json` + `files/<id>.xmind`，每个版本一份完整 `.xmind`）                             |
| 恢复语义               | **保留当前文件路径**并把文档标记为未保存（恢复的是「这份文档的旧内容」，不是换成别的文件）                                  |
| 文档键                 | 按文件路径归并（大小写与斜杠方向不敏感），所以同一文件跨会话共享版本列表                                                    |

### 怎么验收

1. **手动存版本**：随便改几个节点 → 工具栏「更多 → 历史记录与常用」→「版本快照」标签 → 填备注「之前的样子」→「存一个版本」→ 列表出现一条带「手动」徽标与备注的记录，并提示已存。
2. **自动版本**：不手动操作，编辑 10 分钟以上（或重启应用后再编辑一会儿）→ 回到该标签页，应出现「自动」徽标的新版本。**什么都不改时反复等待不会堆出一堆重复版本**（内容没变会被跳过）。
3. **恢复（重点）**：记住当前中心主题的名字 → 把它改掉并加几个节点 → 存一个手动版本 → 再改乱一些 → 在列表里点较早那条的「恢复」→ 画布内容应回到那个版本，并提示「已恢复到所选版本（恢复前的状态也留了一份，可再切回）」。
4. **兜底可回退**：紧接着看列表，应出现一条 **「恢复前」** 徽标的版本；点它恢复 → 应回到步骤 3 里「改乱」的状态。
5. **路径不变**：恢复后看窗口标题与状态栏，文件路径应**仍是原来那个**，标题栏有未保存标记（`●`），`Ctrl+S` 能直接覆盖保存。
6. **未保存文档**：`Ctrl+N` 新建、随便画几笔、**不保存** → 切到「版本快照」标签页，应看到明确提示「这份文档还没有保存过，先按 Ctrl+S 存成 .xmind 文件，之后就会自动累积版本」，而不是一个空白列表或可用的「存一个版本」按钮。
7. **跨会话共享**：保存过的文件，关掉应用重开、再次打开同一文件 → 版本列表应**还在**（版本跟着文件走，不跟会话走）。
8. **删除与清空**：删掉某一条版本 → 该条消失，其余不受影响；点「清空本文档的版本」两次确认 → 列表清空。
9. **磁盘核对**：打开 `%APPDATA%/<应用名>/snapshots/files/`，**文件数量应与列表条目数一致**（删除版本后文件也应被删掉，不留孤儿）。
10. **坏索引不崩**：把 `snapshots/index.json` 改成一段乱码 → 再次打开标签页，应显示为空而不是报错或白屏。

### 本轮自检发现的缺陷（我自己的代码）

| 现象                                                   | 根因                                                                                                                                                                                              |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **每次删除版本都会在磁盘上留下一个回收不到的孤儿文件** | `removeSnapshot` / `clearDocSnapshots` 先把条目从索引里过滤掉、再交给裁剪函数，于是这些条目**不在裁剪函数的输入里**，自然也不会被上报为「需要删文件」。已改为在过滤时先收集被移除的 id 并一并上报 |
| 手改坏的索引条目同样会留下孤儿文件                     | `normalizeSnapshotIndex` 直接丢弃坏条目却不上报其 id。已补上（并加了安全字符校验，避免坏 id 指到别的文件上误删；重复 id 不报，防止误删仍在引用的文件）                                            |

### 设计上被否决的一版（值得记一笔）

第一版我让「未保存的文档」也能有版本，用会话序号分组。自检写完后发现这会引出**三个连锁问题**：

1. 会话序号每次启动从 0 开始 → **重启后新的未保存文档会看到上一次未保存文档的版本**；
2. 文档首次保存后键从 `untitled:n` 变成 `file:路径` → **保存前存的版本全部失联**；
3. 用户丢掉一份未保存文档时，它的版本文件**永远留在磁盘上没人回收**。

根因是「给一个没有身份的东西造了个假身份」。最终按需求原文（「**文件**历史快照」）收紧为**只服务已保存的文件**，三个问题一起消失，API 还少了一个参数。未保存内容本来就由「自动保存 + 崩溃恢复」负责，职责不重叠。

### 验证方式

- **纯逻辑**：`npm run selfcheck` 中「版本快照」6 组（文档键归并、索引校验与裁剪优先级、增删查、自动快照判定、展示文案）。
- **真实文件系统**：另写临时脚本把主进程的 `snapshot.ts` 用 esbuild 打包（`electron` 换成桩）后在 Node 里跑，实测 **27 项**：真的写盘、同内容不重复写、间隔太近不重复写、删除后磁盘不留孤儿、没有路径时不记录、不同文件互不干扰、清空后目录干净、读回的字节是合法 `.xmind`（PK 头）、坏索引不崩且只清孤儿不误删有效文件。**验证完成后脚本已删除**（不属于项目产物）。

### 已知限制（版本快照）

| 限制                                          | 说明                                                                           |
| --------------------------------------------- | ------------------------------------------------------------------------------ |
| **未保存的文档没有版本**                      | 由设计决定（见上）。这类内容的安全性依赖自动保存与崩溃恢复                     |
| 快照存的是**完整 `.xmind` 包**，不是增量 diff | 单个版本大小≈原文件大小；靠 30 个/文档的上限与「同内容跳过」控制占用           |
| 快照只打包**模型引用的资源**                  | 备注 HTML 里引用的图片（本软件尚未建模的部分）不会进快照                       |
| 不做「按文件大小」的全局配额                  | 只有条数上限；超大图片文档若长期使用需自行清理                                 |
| 恢复不进撤销栈                                | 恢复是一次大跨度替换，撤销栈对它没有意义；安全性由「恢复前自动存一份版本」保证 |
| 文件被改名/移动后                             | 版本列表按路径归属，改名后会视为一个新文件（旧版本的记录留在旧路径下）         |

## 4.14、亿图脑图 `.emmx` 支持

### 背景

`.emmx` 是亿图脑图（EdrawMind / MindMaster）的文件格式。用真实样本排查后发现它**实际有两种**，能支持的程度完全不同：

| 类型                 | 包内结构                                          | 支持程度                                                     |
| -------------------- | ------------------------------------------------- | ------------------------------------------------------------ |
| **ver:2 结构化格式** | `content.json` + `metadata.json`                  | **完整还原**：层级、文字、富文本颜色、节点底色、概要、关系线 |
| **专有二进制格式**   | `document.xml`（只有版面属性）+ `mmpage/page.bin` | **只能提取文字**：层级拿不到，会明确告知                     |

### 做了什么

| 能力           | 说明                                                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 打开入口       | 打开对话框新增「亿图脑图文件」筛选（`.emmx` / `.emm`），也保留「全部文件」                                                                        |
| ver:2 完整解析 | 按 `root` / `children.normal` 递归还原层级；`data.text` 去掉结尾换行；`config.template` 映射成结构（`right` → 逻辑图向右，`mindmap` → 思维导图…） |
| 富文本         | `richText.ops`（Quill Delta）里的 `color` 还原成富文本颜色；**纯文字节点不写富文本**，避免产生冗余数据                                            |
| 节点底色       | `data.background` 存进 `NodeStyle`（Xmind 的 `svg:fill` 键），保存时不丢                                                                          |
| 概要           | `children.summary` 里的节点登记为 `Summary`（区间取 `startId` / `endId`）——**刻意不放进普通子节点**，否则会被同时画成普通主题                     |
| 关系线         | `relativeLinks` 的 `start.nodeId` / `end.nodeId` 还原成关系线，标题取 `text`                                                                      |
| 专有格式       | 扫描 `page.bin` 里的可读文字按出现顺序提取，全部挂成中心主题的一级子节点（结构为「逻辑图向右」，便于当作清单整理）                                |

### 文字提取的规则（在真实样本上调出来的）

- 含中文的段落一律保留；
- 纯 ASCII 要求：以字母开头、含元音、**至少两个小写字母**、不是全大写短词。

最后两条是滤掉 `Vw0E`、`h81E`、`XtD`、`fhj`、`qfy` 这类**格式常量表噪音**的关键，同时能保住 `Tool`、`cpu`、`coze`、`DataFrame`、`df.rename(`、`self-Host`、`Python3` 这些真实节点。另外会跳过 `page.bin` 开头的属性区（那里混着 `Rnewmoren` 这类常量）。

### 真实样本实测结果

用仓库里 4 个真实 `.emmx` 验证：

| 样本                   | 格式       | 结果                                                                                                       |
| ---------------------- | ---------- | ---------------------------------------------------------------------------------------------------------- |
| `Coze初体验.emmx`      | 专有二进制 | 打开成功，提取 **54** 条文字                                                                               |
| `DifyRagflow总结.emmx` | 专有二进制 | 打开成功，提取 **83** 条文字                                                                               |
| `Pandas基础.emmx`      | 专有二进制 | 打开成功，提取 **85** 条文字                                                                               |
| `Pandas进阶.emmx`      | ver:2      | **完整还原 106 个节点**，并还原 **2 条关系线、4 个概要、5 个节点底色、1 处富文本颜色**（与源文件计数一致） |

四个样本都能**打开后重新保存为 `.xmind`，节点数不变**（不只是「看起来能开」）。

### 怎么验收

1. **完整还原的那种**：打开 `samples/Pandas进阶.emmx` → 应看到正确的多级结构（「文件读取 / DataFrame增删查改 / 缺失值处理 / 数据合并」等分支），并且能看到**概要大括号**与**关系线**。
2. **只能提取文字的那种**：打开 `samples/Coze初体验.emmx` → 会弹出提示说明「已按尽力而为的方式提取文字、层级无法还原」；画布上应是一份**扁平清单**，文字内容完整（如「平台介绍 / 智能体 / Coze智能体搭建 …」）。
3. **中心主题名**：专有格式没有自带文档名，中心主题应取**文件名**（如「Coze初体验」）。
4. **能存回去**：打开任意 `.emmx` 后 `Ctrl+S`，应能另存为 `.xmind` 并正常再次打开。

### 已知限制

| 限制                         | 说明                                                                                                     |
| ---------------------------- | -------------------------------------------------------------------------------------------------------- |
| 专有二进制格式**拿不到层级** | 父子关系在 varint 编码的对象图里，需要完整逆向才可能得到；与其猜一个错的层级，不如老实告知并保证文字不丢 |
| 专有格式的**图片不导入**     | 无法定位到具体节点；若强行导入会在文件里留下一堆没有归属的资源                                           |
| 不支持**导出** `.emmx`       | 专有格式没有公开规范；需要时请在亿图脑图里直接导出 `.xmind`                                              |
| 少量短词可能是噪音           | 提取规则无法做到 100% 精确，界面上已提示「核对时留意」                                                   |

## 4.16、拖拽节点（Xmind 同款）

### 一条规则：落点由「指针停在目标的哪个位置」自动识别

不需要事先决定"这次要拖成同级还是子级"，松手位置决定结果：

| 指针停在                                   | 结果                           | 预览                                         |
| ------------------------------------------ | ------------------------------ | -------------------------------------------- |
| 目标**同级排列方向的那一侧**（约外侧 35%） | 插到目标**后面**、与它**同级** | 贴着目标出现**虚线空位框**                   |
| 目标的**本体**（中间区域）                 | 成为目标的**最后一个子主题**   | 目标高亮，空位框落在其**最后一个子节点之后** |
| **两个同级节点之间的空隙**                 | 插到**这两个之间**             | 空位框落在空隙里                             |

三种都只看"指针落在哪 + 实际坐标"，不需要事先选好目标类型，所以**任意两个节点之间都能拖**：
把 A 分支的节点贴到 B 分支某节点的**外侧**，它就成为那个节点的**兄弟**（落进 B 分支）；
停在它**身上**，则成为它的**子主题**。

> **方向是用实际坐标推出来的，不是按结构名写死的。**
> 平衡思维导图的子节点其实是**竖着**排的，若按"父 → 子"的方向去猜，
> 会把"插到下面那个兄弟后面"错画到**右边**，看起来就像要连回根节点。
> 所以：同级方向一律用**相邻两个兄弟的坐标差**来定，
> 子节点生长方向用**最后两个子节点的坐标差**来定，都拿不到时才退回垂直方向。

### 其余落点

| 拖到哪                               | 结果                                                                                                                                    |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| **离最近的主题 260px 以内**          | **就近吸附**：按"指针在它的哪个方向"决定——它外侧＝插到它后面、它身上＝成为它的子主题（4.21 节第 15 条新增，避免主题浮在树外把结构搞乱） |
| **真正的空白处**（离所有主题都很远） | 自由摆放，画布底部会先弹提示条；按住 **`Alt`** 拖拽＝随时强制自由摆放                                                                   |
| 自己的**后代**上                     | 不做任何改动（否则会把子树剪断）                                                                                                        |
| **自己**身上                         | 不做任何改动                                                                                                                            |
| 停在**父级的本体**上                 | 不做任何改动（本来就是它的子主题）                                                                                                      |
| 贴在**父级的外侧**                   | **升一级**，成为父级的兄弟                                                                                                              |

| **除中心主题外，任意主题都能跨级移动** | 已实现：落点由指针位置自动裁决，任意两个节点之间都能拖                                  |

### 拖拽时的视觉反馈

| 反馈                     | 说明                                                                                                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **原连接线断开**         | 父节点连向被拖节点的那条线在拖动期间不画，一眼就能看出「已经摘下来了」                                                                                   |
| **整棵子树一起走**       | 带着子节点拖时，子树内部的连线跟着平移重画，不会留在原地                                                                                                 |
| **插入位置预览（重点）** | 落点处显示一个**虚线空位框**：同级排序时落在目标兄弟之后，成为子主题时落在目标**最后一个子节点**之后；框的大小就是被拖节点的尺寸，能直观看出要占多大地方 |
| **新连接线预览**         | 从未来的父级（排序）或目标节点（成为子主题）拉一条**虚线**接到那个空位上，并已按新关系取好分支色                                                         |
| **抓起来的样子**         | 手里那个节点加投影并置顶，跟着走的子树统一压一点透明度                                                                                                   |
| **空位框里写着标题**     | 提示"哪个节点要落到这里"，比一个空格子清楚得多（对应亿图脑图的吸附/定位符号）                                                                            |

### 本轮修掉的问题

| 现象                                                                                 | 根因                                                                                                                                                 |
| ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 落点**无法自动识别**：拖到兄弟上只是排序、拖到别处只是变子级，想要另一种结果就没办法 | 落点语义被"两者的父子关系"绑死。现在改为按**指针在目标上的位置**判定（外侧＝同级插后、本体＝子主题），并且跨分支也成立，于是任意两个节点之间都能拖   |
| 平衡思维导图里把"插在**下面那个兄弟**后面"的落点画到了**右边**，看起来像要连回根节点 | 方向是按「父节点 → 目标」猜的。平衡导图里同级节点实际是**竖着**排的，于是猜错轴。现在同级方向改用**相邻两个兄弟的坐标差**推断                        |
| 空白处只能**自由摆放**，没法表达"插在这两个中间"                                     | 缺少空隙识别。现在会先找最近的**同级空隙**（两个相邻兄弟之间），命中就按"插到前一个后面"落点，离得远才做自由摆放                                     |
| 在空隙里松手会被当成**自由摆放**、落点丢失                                           | 旧代码只看"有没有命中节点"。空隙命中时节点是没命中的，于是走错分支。现在以"裁决出的落点"为准                                                         |
| 拖到**根节点下的那几个兄弟**之间没有反应                                             | 旧逻辑要求"目标必须是自己的兄弟"才允许排序；根级兄弟虽然满足，但另一条分支（成为子主题）会静默拒绝。已统一到一个裁决函数                             |
| 同级排序**落点会错一位**                                                             | `moveTopic` 是「先摘除再插入」。若被拖节点原本排在目标**之前**，用摘除前的下标插入会整体前移一位，现在改成在「摘除后」的数组上算下标                 |
| 经过关系线下方的**节点拖不动**                                                       | 关系线线身有 18px 的透明命中区、且画在节点**之上**，会把指针事件抢走。已把它单独放到节点**下面**的一层：空白处仍能抓线，被节点压住的地方则优先给节点 |
| 落点非法的节点上松手会**被扔到空白处**（自由摆放）                                   | 旧代码只区分"命中节点"和"没命中"，命中但非法时走进了自由摆放分支。现在非法落点＝什么都不做                                                           |

### 实现上的一点保证

落点裁决抽成了一个纯函数 `resolveDrop`（`src/shared/model/drop.ts`），
**画布上的落点预览**和**真正落盘时的移动**都调用它，
所以不会出现"预览显示插在后面、松手却变成了子主题"这类不一致。
纯函数也让它能被自检完整覆盖：根级兄弟、跨分支、深层互拖、贴父级外侧升一级，
以及各种非法组合都有断言。

### 怎么验收

1. **非根级的同级之间（本轮重点，之前这里出错）**：在「分支主题 2」下建 3 个子主题（就是平衡导图里**竖着排**的那几个）→ 把第 1 个拖到第 2 个的**下缘**松手。空位框应出现在第 2 个的**下方**（而不是右侧），松手后顺序变成「2、1、3」。
2. **视线里的"连回根节点"不该再出现**：上一步拖动时，那条虚线应始终指向**同一层**的位置，不会跑到中心主题那边去。
3. **在空隙里插入（新能力）**：把节点拖到**两个兄弟之间的空白**（贴得不精确也行）→ 应出现空位框，松手就插进这两个中间。若离空隙太远才会变成自由摆放。
4. **同级排序（根级）**：在中心主题下建 3 个子主题，把第 1 个拖到第 3 个的**外侧**松手 → 拖动中应看到**原连接线消失**、贴着目标出现**虚线空位框**、一条**虚线**从父节点接过去；松手后顺序变成「2、3、1」。
5. **反向排序**：把最后那个再拖到中间那个上，顺序应正确（这是上一版会错一位的场景）。（这是上一版会错一位的场景）。
6. **成为子主题**：把 A 拖到另一个**不同父级**的节点 B 上 → 空位框应落在 B 的**最后一个子节点之后**（B 没有子节点就落在 B 之后），松手后 A 成为 B 的子主题。
7. **带子树拖**：拖一个带子节点的主题，子节点与其连线应**整体跟随**，不出现「连线留在原地」的断裂感。
8. **关系线下方**：给两个主题画一条关系线，再去拖动**被这条线经过**的节点，应当能正常拖动（上一版会被线抢走事件）。
9. **拖到空白**：应变成自由摆放；此时父级关系不变（用「节点属性」里的清除位置可复位）。
10. **拒绝的情形**：把节点拖到自己的**后代**上、拖到**自己**身上、拖到**自己的父级**上，都应当什么都不发生。
11. **撤销**：排序、换父级都能用 `Ctrl+Z` 逐步回退。

### 4.21.2 拖拽：这一轮到底改了什么

### 4.21.4 怎么验收这轮改动

1. **默认结构**：重启应用后（或点「文件 → 新建」），新画布应当是**居中主题 + 向右展开的两条分支**，而不是左右各一条。工具栏「结构」下拉里应显示「逻辑图（向右）」。
2. **多选整群拖**：在中心主题下建 4 个一级主题 → 按住 `Ctrl` 点选其中 3 个 → 用鼠标按住**其中任意一个**拖动。应当：① 选择**不塌缩**；② 三个（连同各自子树）一起跟着走；③ 被抓的那个角上有橙色「3 个主题」小标；④ 松手后顺序整体变化，`Ctrl+Z` **一次**全部还原。
3. **边缘自动滚动**：把画布缩放到 50%，让一张大图铺得比窗口宽。抓住一个节点往窗口**左/右边缘**推 → 画布应当持续滚动，节点能一路送到远处；松手或把指针移回中间即停。
4. **Esc 取消**：抓住节点拖到一半按 `Esc` → 节点弹回原位，**不该有任何数据被改**（`Ctrl+Z` 也不该多出记录）。
5. **中心主题不能拖**：把鼠标移到中心主题上，光标应是普通箭头；按住拖动应当没有反应。
6. **落点反馈**：抓住任意主题在画布上移动，能看到① 目标节点**绿色虚线**高亮（要成为它的子主题时）；② 一个写着**被拖主题标题**的**实线**空位框，框下还印着**「将成为子主题」**，并有一条**实线**从目标子节点那一列接过去；③ 换成贴在两个同级之间时，改为**虚线**空位框 + 虚线新连线，同时**目标的父级**被**琥珀色虚线**框出来（接纳方是谁一眼可见）。
7. **向右逻辑图的新节点落点**：把某个还没有子节点的主题作为落点 → 空位框应出现在它的**右侧**（而不是上方）。
8. **折叠的落点**：先把某个带子主题的主题折叠起来，再拖另一个主题到它身上 → 它应当**自动展开**，空位框出现在最后一个子主题之后。
9. **自由摆放过的主题**：先把一个主题拖到空白处（变成自由摆放），再把它拖到另一个主题上松手 → 它应当**落在预览框的位置**（不再是"飘在别处"），撤销后连自由位置一起回来。
10. **吸附（本轮重点，之前"结构全乱"的根因）**：把「分支主题 1」拖到「分支主题 2」**右侧一点点**（**不要**精确压在它身上，差二三十像素也行）→ 应当出现落点框，松手后它成为/插到那个分支里，**不会**变成浮在树外面的自由摆放。随便在画布上多拖几次，只要没拖到"离所有主题都很远"的地方，就**永远不该**出现自由摆放。
11. **自由摆放的提示与入口**：把主题拖到画布上离所有主题都很远的空白处 → 底部弹出**「自由摆放（按住 Alt 可随时切换）」**；按住 `Alt` 拖到任何地方都算自由摆放。自由摆放过的主题周围有**灰色虚线圈**，「更多 → 全部恢复自动布局」可一次全部复位（`Ctrl+Z` 一步撤销）。
12. **反悔与撤销**：排序、换父级、整群自由摆放都能用 `Ctrl+Z` 一步步回退。

## 4.22、拖拽吸附：判定改成「分轴区域」，并修掉一个致命缺陷

> 用户原话：「吸附的逻辑还是不对啊，你看，我把框拉到这里了还能吸附到根节点上」
> → 后续反馈：「跟之前没有多少区别，还是烂完了，**尤其是子节点的吸附判断**」

### 定位过程（重要：真因不是"阈值大小"）

1. 先按截图现象改了显示：同级插入不再把「接纳方父级」框起来（琥珀框会被读成"落到了中心主题上"）；
2. 现象仍在，于是去查成熟开源实现怎么判 —— `wanglin2/mind-map` 的 `simple-mind-map/src/plugins/Drag.js`：
   它**从不使用"到节点的直线距离"**，而是
   **先要求指针落在节点垂直于「同级方向」的投影范围内**，再沿线分三段：
   相邻兄弟缝隙的一半 → 插到前 / 后；落回节点本体 → 成为子节点；全都没命中 → 才自由摆放。
   也就是说，容错窗口天生是**各向异性**的（同级方向只有"那条缝"宽，生长方向是一整片）。
   用一个各向同性的半径去卡，必然一边太松、一边太紧，怎么调都不对。
3. 顺着这条思路复查调用链，找到了真正的致命缺陷（见下）。

### 真缺陷（本轮最关键的修复）

`resolveDrop` 里有一条刻意规则：**多选拖拽禁用「成为子主题」**（一群主题挂到一个人下面解释不通）。
但画布调用时传的第五个参数是 `moving.ids`＝「锚点 + 它整棵子树」，**永远非空**，于是：

> **只要在拖动，「成为子主题」就恒返回 `null` —— 拖到任何主题身上都不吸附、松手什么都不发生。**

自检没拦住它，因为用例调 `resolveDrop` 时**不传第五个参数**（测试与线上调用方式不一致）。

修复：把取参规则抽成纯函数 `alsoDraggedOf(drag, anchor)`（`shared/model/dragmove.ts`），
**画布与自检共用同一份**，并补 4 条回归断言把这个坑钉死。

### 判定模型（现在的规则）

以默认的「逻辑图（向右）」为例（兄弟上下排、子节点向右长）：

| 指针停在                                     | 松手结果                                    |
| -------------------------------------------- | ------------------------------------------- |
| 主题**本体中间**                             | 成为它的子主题                              |
| 主题**本体上缘 / 下缘 28%**                  | 插到它**前 / 后**（同级）                   |
| 主题**生长方向**那片空白（1.5 个横向间距内） | **成为它的子主题** ← 用户截图那个位置       |
| 主题上下方那条缝（1.6 个纵向间距内）         | 插到它**前 / 后**                           |
| 某一层**最外侧**再多留 2.4 个纵向间距        | 仍算插到它后 / 前（方便「追加一个子主题」） |
| 两个同级主题**之间更宽的缝**                 | 插进这两个中间                              |
| 再远的空白                                   | **自由摆放**（按住 `Alt` 强制）             |
| 一级主题 + 思维导图结构                      | 拖到中心主题另一侧 → 左右对调               |

实现要点：

- 新增纯函数 `nearestInRegion`（`shared/model/drop.ts`）：在「可吸附区域」命中的候选里
  取**离本体最近**的（同距取更深）；
- `snapRegionOf`（画布）：按**两条轴分别**外扩出区域（生长方向宽、同级方向窄、最外侧多留）；
- 落点迟滞：换目标前指针要先走够 `DROP_HYSTERESIS`（**世界单位**，随缩放折算）。

### 顺带修掉的体验问题

| 项                     | 说明                                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------- |
| **非法落点不再"无声"** | 底部提示原因：「它已经是这个主题的子主题了」/「多选拖拽只能插到同级之间」。抽成纯函数 `blockReasonOf`，可自检 |
| 不再框「接纳方父级」   | 同级插入只高亮**参照的那个主题**（琥珀虚线 → 蓝色虚线），避免被读成"落到了中心主题上"                         |
| 落点迟滞               | 消除指针停在分界线上时提示"一帧一个样"的乱跳                                                                  |
| 底部图例               | 拖拽时把"这一下会发生什么"对应的那一条**点亮**（三种结果永远只亮一条）                                        |
| 自由摆放               | 只有"离所有主题都远"且不挨着任何主题时才会发生                                                                |

### 怎么验收

1. **成为子主题（本轮重点）**：把主题拖到**另一个主题的方块上** → 目标出现**绿色虚线**高亮 + 写着标题的**实线空位框** + 「将成为子主题」→ 松手后真的成为它的**最后一个子主题**，`Ctrl+Z` 可撤回。
2. **右侧子节点区**：把主题拖到某主题**右侧那片空白**（子节点该在的位置）→ 仍判「成为它的子主题」，**不再**掉进自由摆放。
3. **同级缝隙**：拖到**两个同级主题之间的缝**里 → 出现插入条，松手插进这两个中间。
4. **追加子主题**：拖到**最后一个子主题之后稍远**的空白 → 仍算「插到它后面」＝给父主题追加一个子主题。
5. **多选**：多选后拖到某个主题身上 → 底部提示「多选拖拽只能插到同级之间」，且**不发生改动**。
6. **非法落点**：拖到**自己的父级身上** → 底部提示「它已经是这个主题的子主题了」。
7. **缩放一致性**：把画布缩到 50%，重复 1–3 → 手感应与 100% 时一致（迟滞按世界单位算）。
8. **自由摆放**：拖到离所有主题都很远的空白 → 底部提示「自由摆放（按住 Alt 可随时切换）」。

### 已知限制

| 限制                                                        | 说明                                                                                                                                                     |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 区域外扩量是**固定世界距离**（生长 84 / 同级 29 / 外侧 43） | 不同结构、不同节点尺寸下可能仍需微调；但它们都是显式命名的常量，改一处即可                                                                               |
| **保留**「上/下缘 28% 算插前/插后」                         | 与 Xmind 一致，且用户明确要求保留（拖到第一个/最后一个主题的**外侧边缘**仍是插前/插后）。成熟实现是"本体内部一律算成为子主题、只有缝隙插前/后"，取舍不同 |
| 多选拖拽**只支持同级插入**                                  | 一群主题挂到一个人下面解释不通；现在会给出原因提示，不再静默                                                                                             |
| 落在「已有子节点的主题的最后一个子节点**右侧**」            | 判成"成为那个子节点的子主题"（与成熟实现的列语义一致），不是"追加到父主题"                                                                               |

## 4.23、键盘手感修复：删除 / 新建后的选择、空格与 Enter

> 用户反馈：「1 添加新节点上下左右键选择失效；2 删除节点选择失效，必须鼠标点击才能生效；
> 3 空格写入与折叠子主题冲突；4 按 Enter 是退出当前框，而不是退出当前框并创建下一个框」

### 真缺陷（本轮修复）

| #   | 现象                                     | 根因                                                                                                                                                                            | 修复                                                                                                                                             |
| --- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | 添加新节点后方向键"失灵"                 | `Tab` / `Enter` 建出的节点**立刻进入编辑态**，方向键被编辑器吃掉（光标在空段落里挪，屏幕上什么都看不见）；而导航逻辑当时写死在 `App.tsx` 里，编辑器无从请求"退出编辑并移动选择" | 导航抽成 store 的 `navigateSelection()`；**空主题**上按方向键＝提交并移动选择（空主题本来也没有"段内导航"可言）                                  |
| 2   | 删除节点后选择失效，必须鼠标点一下才恢复 | `deleteSelection` 直接 `set({ selection: [] })`，选择指向"空"；而导航里 `if (index < 0) return`，于是方向键、`Delete` 全体失灵                                                  | 删完把选择落到一个**还存在**的主题上：原位置之后的兄弟 → 之前的兄弟 → 父级；`navigateSelection` 另加兜底：选择指向不存在的主题时自动收回中心主题 |

### 空格与折叠：改为「选中后直接打字即编辑」（用户选 B）

| 项                         | 现在                                                                                                                           |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 选中主题后按任意可打印字符 | 进入编辑，字符**接在原有文字末尾**（不覆盖），光标落在末尾；`空格` 只进入编辑、不落字（见 4.25）                               |
| 折叠 / 展开                | **`Ctrl+/`**（空格已让给"直接输入"）；主题右侧的 `＋` / `−` 小圆点同样可用                                                     |
| 大纲面板                   | 行上按空格仍是折叠 / 展开（那里没有"直接打字"的输入路径，不冲突）                                                              |
| 编辑态下的单键             | 全局快捷键不再接管空格 / Tab / Enter / Delete / 方向键，避免"想打空格却把主题折了"（点过底部格式栏后焦点离开编辑器时尤其明显） |
| 应用内「?」清单            | 同步更新，并补齐之前缺的 `Ctrl+F` / `Ctrl+E` / `Ctrl+H` / `Ctrl+Shift+S`                                                       |

### Enter：只退出，不新建（用户确认）

| 按键                    | 现在                                                         |
| ----------------------- | ------------------------------------------------------------ |
| `Enter`（编辑中）       | **提交并退出编辑**，不顺便新建同级主题                       |
| `Tab`（编辑中）         | 提交并新建**子**主题（它本身就明说了要建一个子级，保持原样） |
| `Shift+Enter`（编辑中） | 段内换行                                                     |
| `Enter`（未编辑）       | 添加同级主题                                                 |

> **这推翻了 4.5 节的旧约定**——那里按用户当时的要求做成了"编辑中 `Enter` 一步完成提交 + 新建"。
> 现在连续录入的节奏变成：`Enter` 建一个 → 打字 → `Enter` 结束 → 再 `Enter` 建下一个。
> 若以后要回到旧行为，store 里的 `commitAndAddSibling()` 仍然保留着，改一行绑定即可。

### 怎么验收

1. `Tab` 建一个空主题，直接按 `↑` / `↓` / `←` / `→` → 选择移动（并退出编辑），不再"按了没反应"。
2. 选中一个主题按 `Delete` → 相邻主题被选中（不是"什么都没选中"），接着按方向键、`Delete` 都还能用。
3. 选中主题按**空格** → 进入编辑并在末尾补一个空格（**不**折叠）；按 `Ctrl+/` 折叠 / 展开。
4. 编辑中按 `Enter` → 只退出编辑，**不会**冒出新的空主题；再按一次 `Enter` 才新建同级。

## 4.24、视角锁定：镜头跟住选中的主题

> 用户要求：「加入视角锁定，锁定到选择的节点」

### 是什么

工具栏最右侧多了一个**准星按钮**（`Ctrl+Shift+L`）：打开后画布**始终把选中的主题按在视口中央**。

| 场景                              | 打开视角锁定后                                                                                                         |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 方向键在主题间移动                | 镜头跟着走，长导图里不用再手动拖画布去找"现在选到哪了"                                                                 |
| 点大纲面板里的行 / 搜索跳转       | 镜头随之移到那个主题                                                                                                   |
| 新建主题（`Tab` / `Enter`）       | 新主题一出现就在视野正中                                                                                               |
| 拖拽重排、撤销 / 重做后节点换位置 | 镜头跟到节点的新位置                                                                                                   |
| **删除主题之后**                  | 选择落到相邻主题（见 4.23），镜头随即跟过去；选择若指向一个已不存在的 id，就**退回中心主题**，而不是"盯不到就干脆不动" |
| 改文字让节点变大 / 变小           | 节点动到哪，镜头跟到哪（选中它的那段时间一直钉着它）                                                                   |
| `Ctrl + 滚轮` 缩放                | 以**选中的主题**为中心缩放，不会被缩放甩出屏幕                                                                         |
| 手动拖动画布                      | 允许——想临时看别处直接拖；下一次选择变化镜头再咬住                                                                     |

### 怎么做的

- 状态放在 store（`viewLock: boolean` + `setViewLock` / `toggleViewLock`），**只影响"看"，不写撤销栈、不影响"未保存"标记**，新建 / 打开文档也不会被重置。
- 画布里是**逐帧缓动**（`requestAnimationFrame`，每帧向目标平移量收敛 22%，收敛到亚像素即停），不是一步跳过去：一步到位时整张图会「啪」地闪一下，眼睛跟不住到底选中了哪个主题；缓动过去才像镜头跟着走。
- 收敛后自动停手，**空闲时不写 store**，不会白转。
- **跟随的触发条件是"被盯住的主题自己的位置/尺寸变了"**（`focusKey`：id + 四舍五入后的 x/y/宽/高），不是"布局对象变了"：
  删掉一整条主题、改文字让节点变大变小、拖拽重排、撤销重做……只要它动了镜头就跟；
  别的分支在动则不会带着镜头乱跑。
- 目标一时不在布局里（刚删完、刚打开）会**重试 30 帧**再放弃，不再因为一帧的时序差就整个不跟。
- 依赖里带上 `zoom`，所以缩放时镜头钉在选中的主题上；**手动拖动画布不会触发跟随**（拖拽 / 框选都不动选择，只有选择或位置真的变了才重新咬住）。

### 三个入口（三处状态一致）

| 入口           | 位置                                                           |
| -------------- | -------------------------------------------------------------- |
| 工具栏准星按钮 | 缩放组最右；按下态＝已锁定，提示语里写明"再点一次取消"         |
| 视图菜单       | 「视角锁定：跟住选中的主题 / 取消」，加速键 `Ctrl+Shift+L`     |
| 状态栏         | 锁定后右侧出现「视角锁定」链接，点一下即取消（不用回工具栏找） |

### 怎么验收

1. `Ctrl+Shift+L` → 状态栏出现「视角锁定」，工具栏准星按钮呈按下态。
2. 连按 `→` / `↓` → 镜头**平滑地**跟着选中的主题走，不是"啪"地跳。
3. 点大纲里的远处行 / `Ctrl+F` 搜到某个主题 → 镜头移到它身上。
4. 手动拖动画布 → 能拖走；再按一次方向键 → 镜头立刻回到选中的主题。
5. 再按 `Ctrl+Shift+L`（或点状态栏「视角锁定」）→ 恢复正常手感。
6. `selfcheck` 有对应断言（**8.5b 组**）：开关往返返回新状态、不写撤销栈、不影响脏标记、新建文档后保持锁定。

## 4.25、输入法存字：空框里不再凭空冒出「空格和 w」

> 用户反馈：「空框输入有时候会自动输入一个空格和w」

### 根因

「选中主题后直接打字就进入编辑」（4.23 选的方案）会把**按键字符直接写进节点**。麻烦在于
**中文输入法组词的第一个字母看起来完全正常**：`isComposing` 是 false、`keyCode` 也不是 229，
代码根本无从分辨——于是拼音 `wo` 的 `w` 被当成普通字符塞进了空框；空格同理（用户按空格
常常只是想用输入法选词，并不是要在标题里加一个前导空格）。

「有时候」也正好由此而来：输入法报 229 时不落字（正常），不报时就落字（冒出怪字符）。

### 怎么修

| 项                   | 现在                                                                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `空格`               | 只用来**进入编辑**，不再补一个空格（空标题里的前导空格没有任何意义）                                                                  |
| 其它字符             | 仍然落字（保住"打字即输入"的手感），同时**寄存一笔**：新增 `renderer/src/editor/typedChar.ts`，记下"这个字符是我塞的、塞在哪个节点上" |
| 输入法真的开始组词   | 编辑器把这个字符**选起来** → 输入法的组词直接替换掉它（不动文档，不打断正在进行的组词）                                               |
| 组词结束它还没被替换 | 兜底删掉                                                                                                                              |
| 用户自己改过文本     | 判断依据是"那段区间里还是不是当初那个字符"；对不上就**绝不插手**——宁可留一个字符，也不能误删用户刚打的内容                            |
| 换了编辑对象         | 寄存按节点 id 认领，换人即作废（`takeTypedChar` 取走即清空）                                                                          |

### 怎么验收

1. **中文输入法**：选中一个主题（**别双击**），直接敲拼音 `wo` → 输入法正常组词、上屏的是中文，
   标题里**不该**留下那个多余的 `w`。
2. **空格**：选中主题按空格 → 进入编辑，但标题里**不该**多出一个空格；真想在标题里打空格，进编辑态后再按一次即可。
3. **英文照旧**：选中主题敲 `a` → 立刻进入编辑，且 `a` 已经在标题里（不用重敲一遍）。
4. `selfcheck` 有对应断言（**8.5c 组**）：同节点可取回、取走即清空、换节点不认、可显式放弃。

## 4.26、编辑态长文本不换行（撑破节点）

> 用户反馈：「输入 aaaa… 这种长串时，编辑框里的文字排成一条长线冲出节点，按 Enter 提交后才换行」

### 根因

编辑态的文字由 ProseMirror 直接排版，尺寸全靠 CSS。从 `.topic__editor` 到内容区，中间每一层都是
**flex 子项**（Tiptap 的 `EditorContent` 还会再多渲一层无样式的 `div`），而 flex 子项默认
`min-width: auto`，下限是**最长不可断片段**——一串没有空格的 `aaaa…`（长 URL 同理）把内层顶得比节点还宽，
浏览器自然就失去了换行的机会。

`word-wrap: break-word`（= `overflow-wrap: break-word`）只决定"怎么断"，**不参与最小内容宽度的计算**，
所以过去写了也没拦住。提交后走的是另一条路：静态文本用**测量阶段算好的行**（`node.lines` 逐行渲染），
所以一按 `Enter` 就"自动换行"了 —— 这正是"输入时不换行、提交才换行"的来源。

### 第一版修法为什么没够（0.2.1 那版）

只改了 CSS：`.topic__editor` / `.rich-editor__content` 加 `min-width: 0`，内容加 `overflow-wrap: anywhere`。
它治住了**已知的两层**，但 Tiptap 的 `EditorContent` 会在 `.topic__editor` 里**再包一层 div**
（见 `@tiptap/react` 的 `EditorContent` 实现：`div` + 把内容搬进去），那一层同样是 flex 子项、
同样带 `min-width: auto` —— 长串照样把它顶宽，内层于是又变回一条长线。**只靠 CSS 收不住所有中间层。**

### 真正的修法：给编辑区一个确定的像素宽度

| 位置                             | 改动                                                                                                                                                     |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `render/measure.ts`              | 把文字宽度上限 `TEXT_MAX_ROOT`(320) / `TEXT_MAX`(240) 导出，编辑态复用同一套常量                                                                         |
| `RichTextEditor.tsx`             | 挂载与尺寸变化时把 `editor.view.dom.style.width` 设成 `min(上限, 节点宽度 − 左右内边距) + 1px`（末尾 +1px 是小数宽度的余量，免得最后一个字被挤到下一行） |
| `styles.css`（0.2.1 那两处保留） | `min-width: 0` + `overflow-wrap: anywhere` 继续兜底：宽度写死之后，超长无空格的串仍需要"任意位置可断"                                                    |

宽度用的是与 `measureTopic` **同一个值**，所以**编辑态的断行位置 = 提交后的断行位置**，提交时不会"跳一下"；
节点高度在编辑态本来就是 `height: auto` + `minHeight: 测量值`（见 `TopicNode`），于是真正做到**边打字边换行、边变高**。

### 怎么验收

## 4.27、从文件管理器打开：双击 .xmind / 拖拽 / 命令行

真正缺的是**从文件管理器进来的三条路**：

| 入口                                    | 之前的现状                                                                         | 现在                                                                                                                                                    |
| --------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 资源管理器里**双击 `.xmind`**           | 安装包没注册关联，双击被系统推给别的软件，或直接报「无法打开」                     | 安装版注册 `.xmind` 关联（`fileAssociations`），双击即开                                                                                                |

- 时序：启动时**不**直接推给渲染进程（那一刻 React 可能还没挂载、监听还没注册），
  渲染进程就绪后 `openFilePending` 取一次即清空；已开窗口的场景走 `fileOpenRequest` 推送。
  两条路都过 `guard`，不会在有未保存改动时静默替换当前文档。
- `.xmind` 关联只由**安装版**注册；免安装版保持绿色、不动系统。

## 4.28、分支上切换结构无效：修好了

| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `layout/core.ts`                   | 新增 `subtreeExtent`（**家族感知**的子树占用：组织架构图是横向铺行、鱼骨图沿主脊展开，再套用垂直堆叠的公式会导致兄弟分支重叠）；新增 `onFinish` 钩子（嵌套结构的装饰要等坐标归一化后再补画） |
| `layout/subtree.ts`（新）          | 分派器：`effectiveStructure`（自己的结构优先，否则继承父链）、`declaresOwnStructure`、`placeSubtree`、`placeMindmapChildren`、`anchorsForChild`（连线锚点按子主题家族选）                    |
| `layout/fishbone-subtree.ts`（新） | 分支级鱼骨图：主脊从分支右侧延伸，一级子主题左右交替，深层堆成缩进列表                                                                                                                       |
| `layout/stack.ts`                  | `placeVerticalChildren` 加 `inherited`：占用按家族算、遇到声明了不同结构的子主题就交给 `placeSubtree`；五个家族布局把根结构往下传                                                            |
| `layout/orgchart.ts`               | 抽出可嵌套调用的 `placeOrgChartChildren`，同样带分派                                                                                                                                         |

v1 支持作为分支结构：**逻辑图（左/右）、树形图（左/右）、思维导图（平衡）、组织架构图（上/下）、鱼骨图**；

### 手动偏移避让（用户反馈「新生成的节点会和老节点重合」）

## 4.38、公式三改：不再截断 + 入口上快捷栏 + 支持 Markdown 写法

### ① 公式被截断（真缺陷）

**根因**：渲染侧 `.topic__formula .katex { font-size: 1.1em }` 把公式**放大 10%**，而测量侧用的隐藏容器（`.formula-measure`）**不在 `.topic__formula` 里、没有这条规则**——于是「算出来的框」比「画出来的内容」小一圈，容器又是 `overflow: hidden`，表现为右/下被切掉。

**修法**：

- 删掉那条 font-size 放大（**测量与渲染严格 1:1**，CSS 里写了注释警示后来人）；
- 测量改用 `getBoundingClientRect()` 拿**亚像素**尺寸并 `ceil + 2px` 余量（`offsetWidth` 取整值正好会切掉一丝边缘）。

### ② 公式 / 代码入口上快捷栏

工具栏新增两个直达按钮：**公式（Σ）**、**代码（</>）**——点开节点面板并**自动聚焦到对应输入框**（与 `Alt+C` 同一套信号机制，`formulaFocusTick` / `codeFocusTick`）。

### ③ 公式支持 Markdown 写法

| 场景          | 处理                                                                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 面板输入      | 粘贴 `$x^2$`、`$$E=mc^2$$`、`\(x^2\)`、`\[x^2\]` 都会**自动剥成纯 LaTeX**（`shared/formula.ts` 的 `normalizeFormulaInput`，可叠加剥离）    |
| Markdown 导入 | `- $E=mc^2$` 这类**整句数学**变成节点的**公式**（标题留空，节点就是一块公式）；独立成行的 `$$…$$` 挂到最近节点、挂不上则生成「公式」子主题 |
| Markdown 导出 | 公式写回 `$$…$$`（独立成行）；**导出 → 导入往返一致**（自检有断言）                                                                        |
| 内容型节点    | 标题为空 + 只有公式/图片/代码时，测量**不再留空标题行**，节点就是那块内容                                                                  |

自检新增「公式：Markdown 数学写法」12 条断言 + 往返公式断言，随全量 **1262 项**通过。

## 4.39、概要成为「一等公民」：可选中、可改字体、删空文字也能找回来

> 用户反馈三连：「概要无法使用节点属性」「概要内容完全删除后只剩一个框，无法再添加文字，只能删掉重建」「概要无法修改字体，它本身应该也是一个节点，应该能进行所有节点操作」

### 根因

概要在数据里本来就有 `style?: NodeStyle`（与主题同一套 `properties` 命名），但**没人读也没人写**：

| 症状             | 原因                                                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------------------- |
| 用不了节点属性   | 概要不是树节点，画布上**没有选中态**——面板只认 `selection`（主题），选中概要后它照旧显示「请先选中一个主题」     |
| 删空文字就点不到 | 画布上概要文字是 `summary.title ? <text> : null`——空文字＝**什么都不渲染**，也没有命中区，于是双击改字也无从触发 |
| 改不了字体       | 字号写死 13、粗细写死 600、颜色取分支配色，样式字段再怎么写都不参与渲染与导出                                    |

### 怎么改

| 层                                             | 改动                                                                                                                                                                                                                                                                        |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 样式读写（新 `shared/model/overlay-style.ts`） | `readOverlayTextStyle` / `withOverlayTextStyle` / `readOverlayFontSize`：用 Xmind 的 `fo:font-size`（`14px` 与 `14` 都认）、`fo:font-weight`、`fo:font-style`、`fo:color`；显式 `undefined` 表示恢复默认（删键），`bold: false` 写成 `normal`（否则会落回「概要默认加粗」） |

| 删除                                           | 选中画布元素后按 `Delete` 删的是它（`deleteSelection` 先看 `selectedOverlay`），删除后清掉选中态                                                                                                                                                                            |

## 4.40、多窗口多文件：一个窗口 = 一份文档

> 第四批：此前整个应用只有一个 `mainWindow`，双击第二个 .xmind 会把当前正在编辑的文档顶掉。

### 改了什么

| 项            | 之前                                               | 现在                                                                                                                    |
| ------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 窗口          | 全局单例 `mainWindow`                              | **窗口注册表** `Map<webContents.id, DocWindow>`：每个窗口一份独立文档（内容、撤销栈、视图状态各管各的）                 |
| 打开文件      | 一律塞进那一个窗口                                 | **双击 / 命令行 / 二实例** → 已经开着同一个文件就**聚焦那个窗口**，否则**开新窗口**；拖进窗口的文件仍在**那个窗口**打开 |
| 图片/附件资源 | 全局 `loadedResources`，保存时把所有人的图都打进去 | 资源挂在窗口上：**保存只打自己这一份**（跨窗口资源表只在 `mind-resource://` 协议读取时用，路径全局唯一）                |
| 自动存档      | 单一 `autosave/current.xmind`，两个窗口互相覆盖    | **每窗口一个槽位** `autosave/slot-N.xmind`(+`.json`)，新建/保存各自清理自己的槽位                                       |
| 退出确认      | 只问一个窗口                                       | **每个窗口都问**：全部确认（或已不可用）才真的退出                                                                      |
| 对话框与消息  | 全部挂在 `mainWindow` 上                           | 用 `BrowserWindow.fromWebContents(event.sender)`：对话框/标题/关闭回执都落在**发起窗口**                                |
| 菜单          | —                                                  | 「文件 → **新建窗口**」（`Ctrl+Shift+N`），主进程直接处理                                                               |

### 关键设计

- **单实例 ≠ 单窗口**：保留单实例锁（两个进程同时读写同一份自动存档与主题文件会互相覆盖），多窗口由本进程内管理；二实例带文件时走 `openDocumentSomewhere`。
- **同一个文件不开两个窗口**：渲染层在标题栏更新时上报「本窗口当前文档路径」（`window:document-path`），主进程用**路径归一**（大小写、`\` 与 `/`、末尾斜杠都算同一个）判断该聚焦谁。
- **正常关闭即清槽**：正常关窗（含"丢弃未保存改动"）会删掉自己的自动存档，避免下次启动弹出一个「幽灵恢复」；**真崩溃**时该事件不触发，存档留着给恢复用。
- **崩溃恢复只问第一个窗口**（`primaryWindowId`）：多窗口会话里其余窗口的存档仍各自留在 `autosave/` 下，但不主动询问；下次有窗口占用同一槽位时会按新文档处理。

### 怎么验收

1. 菜单「文件 → 新建窗口」（`Ctrl+Shift+N`）→ 出现第二个窗口，两个窗口各自编辑，互不影响 ✅
2. 窗口 A 打开 `a.xmind`，再双击资源管理器里的 `a.xmind` → **聚焦 A**，不会开出第二个窗口 ✅
3. 双击 `b.xmind` → **新开一个窗口**打开它，A 的文档没被打断 ✅
4. 窗口 A 插入图片、窗口 B 也插入图片 → 分别保存 → 各自包里只有自己的图片（互不串）✅
5. 两个窗口都有未保存改动 → 菜单「退出」→ **两个窗口都会被问**，全确认后才退出 ✅
6. 关掉一个有未保存改动的窗口 → 问完再关；重开应用**不会**弹出幽灵恢复 ✅
7. `selfcheck`「多窗口：路径判定与存档槽位」组 10 条断言，随全量 **1313 项**通过 ✅

## 4.41、三处修复：代码块真语法高亮 / 标签不再被切半个字 / 关系线与概要可选可删

> 用户反馈：「① 代码块切到 Python 仍没有语法高亮；② 标签过长被截断；③ 关系线与概要无法被选中或删除」

### ① 代码块：从"标注语言但不上色"到**真高亮**

此前代码块只把语言名存下来、显示在右上角小标里，**没有任何着色**（第一版刻意没做）。
现在补上 `src/shared/code/highlight.ts`：**零依赖、无 DOM 的逐行分词器**。

| 设计点             | 说明                                                                                                                                                                                                     |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 为什么不用第三方库 | 画布（DOM）、导出（SVG/Canvas 绘制指令）、自检（Node）三处共用同一份结果，带 DOM 依赖的库至少在一处用不了；代码块是等宽排版，颜色不影响几何，规则够用即可                                                |
| 支持语言           | 与下拉一致：js / ts / python / java / c / cpp / csharp / go / rust / sql / json / yaml / bash / html / css（含 `py`/`ts`/`js`/`yml` 等别名；`text` 或未知语言＝不高亮，行为与旧版一致）                  |
| 识别能力           | 行/块注释、字符串（含 Python 三引号跨行）、数字、关键字、字面量、内建名、**函数名**（标识符后接 `(`）、**类型名**（大写开头）、JSON/YAML 的键、HTML 标签与属性、CSS 选择器与属性、SQL 关键字不区分大小写 |
| 铁律               | 每行 tokens 首尾拼回去必须**逐字节等于原行**——渲染与测量都按最终文本画，分词一旦改空白或丢字，代码块就会和源码不一致（自检里有这条断言，17 组样本全过）                                                  |
| 画布               | `TopicNode` 按 token 上色（注释斜体），几何不变                                                                                                                                                          |
| 导出               | `drawing.ts` 逐 token 画：横向偏移按「等宽字符数 × `CODE_CHAR_WIDTH`」推进，与 `codeBoxSize` 的估宽用同一单位，导出与画布的换行位置一致（SVG / PNG / PDF 同样有色）                                      |

### ② 标签：按**测量宽度**截断，不再切半个字

根因：测量把标签宽度封顶（`LABEL_MAX_WIDTH`）后，渲染仍把**全文**塞进固定宽度的胶囊里，
由 CSS `overflow: hidden` 去裁——裁的是像素，于是出现"半个字被切掉"。

修法：把截断挪到测量里（`shared/layout/label-fit.ts`，纯函数、字宽由调用方注入）：
逐字试、留出省略号的位置，**画出来的一定是完整字形**；宽度上限同时从 130 提到 170，
被截断时 `MeasuredLabel.full` 带上原文，标签 hover 用 `title` 显示全文。

### ③ 关系线与概要：可选、可删

根因是 CSS 层面的：`.canvas__edges / .canvas__overlay` 整体 `pointer-events: none`，
上一版给概要加的命中区（`.overlay-hit`）**忘了显式打开 pointer-events**，等于没画；
关系线则只有"拖线身改弯度"，点一下什么都不发生。

| 改动                                   | 说明                                                                                    |
| -------------------------------------- | --------------------------------------------------------------------------------------- |
| `.overlay-hit { pointer-events: all }` | 概要与关系线标题的命中区真正生效（注释里写明了这个坑）                                  |
| 关系线线身                             | `pointerdown` 先**选中**再允许拖弯度——点一下就有反馈，不再是"点了没反应"                |
| 关系线标题区                           | 新增透明命中矩形（空标题也有），带虚线选中框                                            |
| 概要与边界                             | 命中区改用统一的 `pickOverlay`：选中 + **自动打开节点属性面板**，文字/字体/删除就在眼前 |
| 删除                                   | 选中后按 `Delete` 删除（`deleteSelection` 优先处理画布元素），`Ctrl+Z` 可撤销           |

### 怎么验收

1. 节点上手选语言为 `python`（或面板里选）→ 代码立即变成 Python 配色：`def`/`return` 关键字、字符串、`#` 注释 ✅
2. 导出一张含代码块的 PNG → 颜色与画布一致 ✅

## 4.42、六项修复：代码块完整展示 / 画布多开 / 折叠徽标 / Typora 全格式 Markdown

> 用户反馈：①「代码块不合格」②「画布功能不就是为了多开吗？同一窗口只能新建画布」③「显示数量有些遮挡，不美观」④「我需要完整的展示整个代码，长宽不限」⑤「A[^1] 这种 markdown 格式还是不支持，我需要支持 Typora 支持的全部 markdown 格式」⑥「多窗口开发者模式无法验证」

### ①④ 代码块：不再滚动、不再截断，长宽随内容

之前代码块有 `CODE_MAX_WIDTH = 320`（列宽封顶）与 `CODE_MAX_LINES = 14`（行数封顶），
超出部分靠内部滚动条——这正是"代码被截断"的来源。现在：

| 项   | 之前                                                           | 现在                             |
| ---- | -------------------------------------------------------------- | -------------------------------- |
| 列宽 | 封顶 320px，超出横向滚动                                       | **按最长行铺开**，只留 96px 下限 |
| 行数 | 封顶 14 行，超出纵向滚动                                       | **全部行都画**，高度随行数增长   |
| DOM  | `.topic__code { overflow: hidden }` + `pre { overflow: auto }` | 两处都改成 `visible`，不出滚动条 |
| 导出 | `slice(0, CODE_MAX_LINES)` 截断                                | 全部行照画                       |

### ② 画布多开：同一文件可以开在第二个窗口里并排看

画布（标签页）是**文档内部**的东西，一个窗口里同时只能看一张——想并排看两张，
只能再开一个窗口。新增：

- 菜单「文件 → **在新窗口打开当前画布**」
- 工具栏「更多▾ → **新建窗口** / **在新窗口打开当前画布**」（开发者模式下也能直接点，见⑥）

实现：新窗口带着 `{ path, sheetId }` 打开同一份文件，就绪后自动切到指定画布
（`window:open-sheet` + `window:pending-sheet`）。当前窗口有未保存改动时先走确认——
新窗口读的是**磁盘上的那份文件**。

> 与「双击同一个 .xmind 聚焦已有窗口」并不冲突：双击是**防误开**（同一个文件在两个窗口里改会互相覆盖），
> 而菜单/工具栏入口是**明确要并排看**。两个窗口各自保存时，后保存的覆盖先保存的（与多数软件一致）。

### ③ 折叠数量徽标：移到节点外侧

之前徽标 `right: -8px` 骑在节点边框线上、还会压住连线。现在整体移到**节点外侧 6px**
（`left: calc(100% + 6px)` / `right: calc(100% + 6px)`），并给一圈**画布底色的描边**
（`box-shadow: 0 0 0 2px <画布色>`），压在连线上也读得清；胶囊也收小了一号。

### ⑤ Markdown：补齐 Typora 的行内语法

行内解析器从"一个大正则"换成了**扫描器**（`parseInlineMarkdown`），新增：

| 语法                                                  | 结果                                                                                   |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `==高亮==`、`<mark>`                                  | 富文本新增 `highlight`：画布上有底色，导出（SVG/PNG/PDF）先铺色块再画字                |
| `^上标^`、`~下标~`、`<sup>`/`<sub>`                   | 富文本新增 `script`：字号按 0.72 倍参与排版，渲染时上下偏移（SVG 用 `baseline-shift`） |
| `[^1]` 脚注引用 + `[^1]: 说明` 定义                   | 引用渲染成上标，**定义补进该节点备注**（标题/列表/段落三种位置都支持）                 |
| `[TOC]`                                               | 跳过，不生成节点                                                                       |
| `[文字][引用]` / `[引用]` + `[引用]: url` 定义        | 解析成链接，url 挂到节点超链接                                                         |
| `<u>`/`<b>`/`<i>`/`<s>`/`<code>`/`<br>`、其它标签剥离 | 转成对应富文本；`&amp;`/`&#65;` 等实体解码                                             |
| `\*` 等反斜杠转义                                     | 按字面字符                                                                             |
| 孤立的 `*`/`~`/`^`（如 `2 * 3`）                      | 保持原样，**不会**被当成格式开关吞掉后面的文字                                         |

编辑器同步：新增 `highlight` / `superscript` / `subscript` 三个 TipTap mark，
**编辑标题时这些格式不会被丢掉**；Markdown 导出反过来写 `==` / `^` / `~`，与导入器构成往返。

### ⑥ 开发者模式怎么验多窗口

`npm run dev` 用的是**单实例锁**（防止两个进程互写同一份自动存档与主题文件），
所以"再开一次 dev"不会得到第二个窗口。验证走应用内入口即可：

1. 工具栏「**更多▾** → 新建窗口」（或 `Ctrl+Shift+N`）→ 出现第二个窗口；
2. 在窗口 A 里点「更多▾ → **在新窗口打开当前画布**」→ 新窗口打开同一份文件的指定画布（未保存时先问你要不要保存）；
3. 两个窗口分别改动、分别 `Ctrl+S`，或分别关窗看是否有各自的未保存提示。

### 怎么验收

1. 贴一段 30 行、每行很长的代码 → 代码块**整段铺开**，没有滚动条、没有被切掉的字符 ✅
2. 加个长标签 → 胶囊里是完整字形 + `…` ✅
3. 折叠一个有 40 多个后代的主题 → `+44` 徽标在**节点外侧**，不压边框与连线 ✅
4. 导入含 `==高亮==`、`H~2~O`、`x^2^`、`A[^1]` 的 md → 画布上有底色与上下标，脚注说明出现在节点备注里 ✅
5. 导出 PNG → 高亮底色与上下标都在 ✅
6. `selfcheck` 新增「Markdown：Typora 全格式行内语法」28 条断言，随全量 **1401 项**通过 ✅

## 4.43、四项修复：代码块随节点缩放 / 画布副本 / 徽标微调 / 行内 Markdown 即时生效

> 用户反馈：①「代码块拉伸节点后会脱离节点框，它应该像图片一样有缩放功能」②「画布多开还是不行——我要的是 A 画布新建 B 画布，B 能正常导入导出且不影响 A，两者共存互不影响」③「徽标这样连接更美观（再收一收）」④「`A[^1]`、`==高亮==` 还是不能正常使用」

### ① 代码块：像图片一样随节点等比缩放

根因：上一轮为了让代码"完整展示"去掉了列宽/行数上限，但**尺寸不再受节点约束**——
节点被拉小时，代码块还按自然尺寸画，于是"跑出节点框"。

修法：`codeBlockMetrics(code, bounds?)` 一次给出**全套指标**（缩放系数、字号、行高、内边距、头部高度、宽高）：

| 场景         | 行为                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| 节点没被拉伸 | 保持自然尺寸（完整展示，不滚动）                                         |
| 节点被拉小   | 按可用空间**等比缩放**（字号/行高/内边距一起缩），并做取整回调确保塞得进 |
| 节点被拉大   | 跟着放大，最多 2 倍（和图片的 `IMAGE_GROW_LIMIT` 同一套思路）            |
| 空间再小     | 缩放下限 0.5 —— 宁可略大也不糊成一团                                     |

渲染（画布）与导出（SVG/PNG/PDF）都取同一份指标，不会再出现"测量说这么大、画出来那么大"。

### ② 画布多开 → 改成「在新窗口打开**画布副本**」

上一版的「在新窗口打开当前画布」打开的是**同一个文件**——两个窗口都会写回那个文件，
谁后保存谁覆盖，所以谈不上"互不影响"，而且没保存过的文档还开不了。

现在改成**副本**：把当前文档（含未保存改动与图片资源）序列化成一份临时副本，
新窗口打开它但**不认路径**——

- 在副本里导入 / 导出 / 保存（提示另存为）**都不会碰到原文档**；
- 原文档继续编辑也不影响副本：两边完全独立；
- 未保存过的新文档同样能开副本（不再有「先保存才能开」的限制）；
- 关窗即删临时文件，启动时顺手清理超过一天的历史副本。

入口：菜单「文件 → 在新窗口打开画布副本」、工具栏「更多▾ → 在新窗口打开画布副本」。

### ③ 折叠徽标：贴着节点外侧，外圈更轻

间距 6px → 5px，画布底色的外圈从 2px 收到 1.5px、阴影更淡——贴着节点但不压边框。

### ④ Markdown 行内语法**在编辑器里即时生效**

上一版只在"导入 Markdown 文件"时解析这些语法；用户直接在节点里输入/粘贴时当然还是纯文本。现在补上两条路：

| 输入方式 | 行为                                                                                                                                     |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **打字** | TipTap 输入规则：输入 `==高亮==`、`^上标^`、`~下标~`、`[^1]` 立刻变成对应格式（Typora 的手感）                                           |
| **粘贴** | 剪贴板里是**单行纯文本**且解析后确实变了（标记被吃掉）时，按语法落地成富文本；带 HTML 的富文本粘贴、多行文本一律走默认行为，不会被误解析 |

配套：`runsToHtml`（run → HTML，含转义）把解析结果交给编辑器 schema，与画布上的呈现一致。

### 怎么验收

1. 加一个代码块，拖节点右下角手柄**拉小** → 代码块跟着缩小、**待在框里**；拉大 → 跟着放大（最多 2 倍）✅
2. 工具栏「更多▾ → 在新窗口打开画布副本」→ 新窗口出现；在副本里导入一个 md、导出图片、`Ctrl+S`（提示另存为）→ 原窗口内容**一点没变** ✅
3. 折叠一个有 40+ 后代的主题 → 徽标贴在节点外侧、外圈更轻 ✅
4. 在节点里**直接输入** `==高亮==`、`H~2~O`、`x^2^`、`A[^1]` → 立刻变成高亮/下标/上标；**粘贴**同样生效 ✅
5. `selfcheck` 新增代码块缩放 10 条、`runsToHtml` 6 条断言，随全量 **1416 项**通过 ✅

## 4.44、三项修复：框不小于代码块 / 打开不再覆盖当前画布 / 徽标贴合 + 粘贴识别 Markdown

> 用户反馈：①「框的最小大小不能小于代码块大小」②「为什么我在画布 2 导入文件会覆盖画布 1？」③「悬空不好看，最好还是和节点有部分重叠」④「粘贴还是无法识别 markdown」

### ① 节点框不能小于代码块

根因：代码块最小只能缩到 `CODE_MIN_SCALE = 0.5`（再小看不清），但**拉伸手柄的下限是写死的 60×28**——
于是可以把框拖得比代码块还小，代码块就溢到框外（用户截图里正是这个）。

修法：`codeMinNodeSize(code, padding)` = 代码块**缩放下限时的尺寸 + 节点内边距**，然后：

- 拉伸手柄按它夹（`minWidth / minHeight`）；
- `setSizeOverride` 里再夹一次（**双保险**：不管谁调、从哪条路径调，框都不会小于内容）。

### ② 「打开 / 导入 .xmind」不再覆盖当前画布

根因：`file:open`（含「打开 / 导入 .xmind…」）是**替换整个文档**——当前文档的所有画布
（画布 1、画布 2…）会被整份换掉。用户看到的就是"导入文件把画布 1 覆盖了"。
（「导入 Markdown / OPML」不同：它只是**新增一张画布**，不动其他画布。）

修法：打开文件时先看当前窗口是不是**空白未改动**的新文档：

| 当前窗口                     | 行为                                                       |
| ---------------------------- | ---------------------------------------------------------- |
| 空白新文档（无路径、无改动） | 就地打开（不浪费窗口）                                     |
| 已有内容                     | **在新窗口打开**，当前文档（含所有画布）保持原样，并给提示 |

拖动 / 双击 / 命令行送来的文件同理（走同一个 `receiveExternalFile`）。

### ③ 折叠徽标：一半压在节点边缘上

按反馈把徽标从"外侧悬空"改成**部分重叠**：`left: calc(100% - 8px)`（左向分支对称），
看起来是"长在节点上"，不再显得突兀。

### ④ 粘贴 Markdown：三条路径全通

上一轮只处理了"编辑态 + 纯文本"这一种情形，用户的实际操作基本都会绕过它。现在补齐：

| 场景                              | 处理                                                                                           |
| --------------------------------- | ---------------------------------------------------------------------------------------------- |
| **编辑态**粘贴（剪贴板里有 HTML） | 只要纯文本本身明显是 Markdown 标记就抢过来解析（`looksLikeMarkdown`），不再因为"带 HTML"就放弃 |
| **选中节点**、没在编辑时 `Ctrl+V` | 剪贴板文本含 Markdown 标记 → 逐行解析成**带格式的子主题**（高亮/上下标/脚注都在），一步撤销    |
| 从文件导入                        | 4.42 起就支持（导入器路径）                                                                    |

`Ctrl+V` 现在的顺序是：剪贴板图片 → 带 Markdown 标记的文本 → 内部复制的节点。

### 怎么验收

1. 加代码块 → **把节点拖到最小**：到一定程度就拖不动了，代码块始终在框内 ✅
2. 在画布 2 上菜单「打开 / 导入 .xmind」选一个文件 → **新窗口**打开它，画布 1 原样不动 ✅
3. 折叠一个有后代的主题 → `+44` 徽标**一半压在节点上** ✅
4. 从 Markdown 编辑器复制 `A[^1]` / `==高亮==`：
   - 双击节点进入编辑后 `Ctrl+V` → 直接变成上标/高亮；
   - 选中一个节点直接 `Ctrl+V` → 生成一个带格式的子主题 ✅
5. `selfcheck` 新增代码块最小尺寸 4 条、Markdown 识别 8 条断言，随全量 **1428 项**通过 ✅

## 4.41、多文档标签：底部任务栏式的「浏览器标签页」

> 需求：把多文件做成浏览器网页/任务栏那样的**标签页**——标签栏横在窗口底部（状态栏上方），点标签切换画布；多窗口保留但弱化。

### 设计

| 决策                                   | 理由                                                                                                                                                 |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `useEditor` 仍是**激活文档**的唯一真相 | 1400+ 行的 store 一行不改，全部既有功能零回归                                                                                                        |
| 新增 `store/tabs.ts`：标签 = 快照      | 切走时把 workbook、撤销栈、视图（zoom/pan/锁定）、选中态整体拍成快照存回标签；切入时整体灌回。非激活标签的数据**不可能被改坏**（编辑器里根本没有它） |
| 永远至少一个标签                       | 关掉最后一个：窗口留下、换成空白新文档（与浏览器一致）                                                                                               |
| 只有一个「空白未改动」标签时就地替换   | 双击第一个文件不会给你留一个空标签；替换沿用原 docId（主进程资源登记不换钥匙）                                                                       |
| 激活标签实时态以编辑器为准             | 标签上的 ● 与文件名直接读编辑器；`findByPath` 对激活标签也用实时路径                                                                                 |

### 改动

| 层          | 内容                                                                                                                                                                                                                                                                                                                                          |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| IPC         | 资源类/读写类调用第一个参数都是 **docId**（openDialog/openPath/saveToPath/saveAs/autosave/pickImage/pasteImage/addImage/pickAttachment/recoveryLoad/snapshotCreate/snapshotRestore）；`documentReset` 换成按文档释放的 **releaseDoc**（关标签时丢掉该文档的资源表）；`reportDocument(docId, path)` 按标签上报                                 |
| 主进程      | `DocWindow.docs: Map<docId, {resources, inserted, docPath}>`——**资源按文档隔离**：A 标签保存只打自己那份图片，A 删图不会清掉 B 的资源；`mind-resource://` 协议跨窗口跨标签按全局路径查找；`openDocumentSomewhere`：已开着 → 聚焦窗口并推 `fileOpenRequest`（渲染层切到那个标签），没开过 → 交给聚焦窗口**开新标签**，一个窗口都没有才新建窗口 |
| 退出        | 逐个切到**每个脏标签**前问未保存确认（对话框显示那份文档自己的名字），全部有着落才真退出                                                                                                                                                                                                                                                      |
| TabBar 组件 | 底部任务栏：文件名 + 脏标记 ● + 关闭 ×、悬停显示完整路径、**拖拽排序**、放不下时**左右箭头滚动**、中键关闭、末尾「+」新建标签                                                                                                                                                                                                                 |
| 顺带收尾    | 上一批遗留的多画布移除收尾：删除孤儿组件 SheetTabs、SearchPanel 去掉跨画布跳转、AI「生成新导图」补上 App 侧 `openGeneratedInNewWindow`（新窗口独立文档）、selfcheck 中依赖已删 sheet API 的断言全部改写                                                                                                                                       |

### 已知边界

- **自动存档按窗口槽位**：崩溃恢复只还原**激活标签**的最后状态；其他标签未保存的内容在崩溃时会丢（正常关窗不受影响——每个脏标签都会被问到）。多标签各自的存档槽位留作后续增强。

### 怎么验收

1. 底部出现标签栏；「新建」（Ctrl+N / 工具栏 / 标签栏「+」）→ **新标签**，当前文档原样留在自己的标签里，不需要未保存确认 ✅
2. 双击第二个 .xmind → 当前窗口**新开一个标签**；再双击同一个文件 → **切回已开着的那个标签**（不重复开）✅
3. 两个标签各自编辑、各自撤销栈、各自缩放/平移；切回来全都原样 ✅
4. 未保存的标签显示 ●；关它时弹确认（「保存 / 不保存 / 取消」）；保存保的正是被关的那份 ✅
5. 标签拖拽重排；标签多到放不下出现左右箭头 ✅

## 4.42、上下标终于「摸得着」+ 折叠徽标去高光

> 反馈：「a<sub>1</sub> 这类上标下标依旧无效」「把折叠主题那玩意的高光去掉，看着太难受」。

### 上下标为什么「无效」

渲染链路（测量缩字号 → 画布偏移 → 导出 baseline-shift / Canvas 偏移）和序列化一直是通的，**坏在入口**：

1. 输入规则要求标记前面有**空白或行首**——`a^2^`、`a~1~` 这种紧贴在字符后面的写法完全不触发；
2. 格式栏里**根本没有**上/下标按钮，功能藏得只有看过文档才知道。

改法：

| 层                               | 改动                                                                                                          |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 输入规则（`RichTextEditor.tsx`） | 前缀从「吞掉一个字符」的 `(?:^                                                                                | \s)`改成 **lookbehind**`(?<=^ | \s)`——不吞字符，`a^2^`/`a~~1~~` 紧贴写法立即生效（`~~删除线~~` 不受影响，下标规则匹配不到它） |
| 格式栏（`RichFormatBar.tsx`）    | 加 **上标 / 下标** 按钮（X² / X₂ 图标，lucide `Superscript`/`Subscript`），选中文字点一下就变；激活态互斥显示 |
| 格式状态（`formatStore.ts`）     | `script: 'super' \| 'sub' \| null`，按钮高亮跟随选区                                                          |

其它入口本来就能用：粘贴富文本 HTML（`<sup>/<sub>`）、粘贴纯文本里的 Markdown/HTML 标记（走 `parseInlineMarkdown`）。

### 折叠徽标去高光

`TopicNode` 给折叠徽标注入的 `boxShadow`（画布色白圈 + 投影）看起来像一圈发光的高光，整体去掉——现在是**纯分支配色的平面圆片**，白字 `+N` / `−` 不变。

### 验收

1. 编辑节点时输入 `a^2^`（不用加空格）→ 立即变成 a²；`a~1~` → a₁ ✅
2. 选中文字点格式栏的上/下标按钮 → 生效，按钮亮起；再点一下取消 ✅
3. 从网页复制带上/下标的内容粘贴 → 保持 ✅
4. 画布、导出 PNG/SVG/PDF 三处上下标一致 ✅
5. 折叠徽标不再有白色外圈与投影，扁平干净 ✅
6. typecheck 零错误、自检 1426 项全绿、构建通过 ✅

## 4.43、设置分发到「子位置」+ 工具栏右键收纳 + 连线消失修复

> 反馈：「不要专门开一个设置放二级设置，太抽象了，所有设置应该在各自的子位置配置」「所有快捷功能都应该有独立图标并支持放入省略号里或快捷栏」「节点间连线过长可能会导致连线消失」。

### 设置：从「集中对话框」到「就地配置」

集中式设置对话框**整个删除**（菜单项也去掉），`settings.json` 仍是唯一真相，但每个配置项住在它自然的位置：

| 设置                   | 新家                             | 生效方式                                                                                                     |
| ---------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 默认字体 / 字号 / 颜色 | 格式栏右端 **⚙默认** 面板        | **首次命名**的新建节点自动套用（只补缺失属性，显式格式不覆盖）；「应用到全部现有节点」一键刷存量（一步撤销） |
| 默认对齐               | 同上                             | 渲染兜底值，立即对**所有未显式对齐**的节点生效                                                               |
| 默认视角锁定           | 同上面板 + 「更多 ▾」开关        | 新开文档的初始状态                                                                                           |
| 默认主题               | 主题面板底部「**设为默认主题**」 | 新建文档自动套用                                                                                             |

关键语义：默认样式只认「**原来标题为空**」的首次命名——改老节点的文字绝不会被突然换字体/颜色；粘贴/AI 带来的显式格式不被默认值覆盖（只补缺失的字体/字号/颜色）。

### 工具栏：独立图标 + 右键收纳

- 每个快捷功能都是独立图标；
- **右键任意图标** → 「收进更多 ▾」；「更多 ▾」顶部出现「已收纳」区，行尾 ↩ 一键**移回快捷栏**；
- 收纳状态持久化（`toolbarHidden`），默认全部展示（行为与旧版一致）；
- 「更多 ▾」同时新增「启动时默认开启视角锁定」开关。

### 修复：长连线消失

连线裁剪之前按「**两端节点是否可见**」过滤——长连线的两端都被裁出视口时，即使线身横穿屏幕中央，整条线也会凭空消失。改为按**边的包围盒**（两端节点矩形外接框 + 余量）与视口求交，横穿屏幕的长连线始终可见。

### 验收

1. 编辑节点 → 格式栏 ⚙默认 → 选字体「楷体」/ 字号 18 / 颜色绿 → 新建子主题打字 → 自动是楷体 18 绿 ✅

3. 「用当前格式设为默认」→ 选区上的字号/颜色/对齐成为默认 ✅

### 2026-09-14 · 撤销粒度统一 + 编辑态双份真相收敛 + 旧名残留清理

#### 一、撤销粒度：什么能合并、什么绝不能

| 操作                                  | 粒度                               | 依据                                                                                                                              |
| ------------------------------------- | ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 连续调色 / 拉伸尺寸 / 改主题配色      | 连续手势**合并成一步**             | 只**替换某个值**，immer patch 的 inverse 不含下标，合并安全                                                                       |
| 连续折叠同一主题（同方向）            | **合并成一步**                     | 同上，只是把 `collapsed` 换成另一个值；**方向一变（折叠→展开）另起一步**，否则「折叠又展开」会被并成一次空操作，撤销看起来没反应  |
| `↑`/`↓`/`Home`/`End`/`←`/`→` 移动主题 | **每次按键各记一步（刻意不合并）** | 移动是**数组重排**，immer 的 patch 带下标；合并后的 inverse 仍按第一步的下标算，套到第二步之后的状态上会**错位、改坏 `children`** |

最后一行是本轮**真实踩到的坑**：一开始把连按方向键并成一步，自检立刻报出 `["甲","乙","甲"]`（`丙` 被覆盖掉了）。结论已写进代码注释：

> 合并只对「替换某个值」类操作安全；凡会重排数组的（移动、拖拽落点），必须一次一步。

要让「连按方向键只撤一次」，得把撤销从 patch 合并改成「存合并组的起始快照」，属于另一套历史模型，本轮没有改。

#### 二、编辑态：两个字段不再各写各的

编辑态 = `editingId`（在编辑谁）+ `editingText`（纯文本）+ `editingRich`（富文本）。
而纯文本与富文本**本来就是同一份内容的两种表示**（面板要纯文本、富文本编辑器要 Delta），
此前有 **14 处**各自手写这三行，漏一处就漂移。现在收敛成两个唯一来源（`src/renderer/src/store/editor.ts`）：

| 唯一来源               | 作用                                               |
| ---------------------- | -------------------------------------------------- |
| `NO_EDITING`           | 退出编辑态的空值，所有「退出编辑」的位置只引用它   |
| `editingContent(rich)` | 给一份富文本，**纯文本由它算出来**——两字段永远同源 |

于是「一边变了、另一边没变」从根上不可能发生；以后新增退出编辑的代码路径也不会漏字段。
