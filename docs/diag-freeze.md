# 卡死排查手册（探针 / 判读 / 复现）

> 复现场景（用户实测）：**命令 AI 一次性给 10–15 个节点补全代码块**时界面冻死数分钟。
> 本文是这套探针的用法与判读表——目标是在渲染进程被堵死、调试端口进不去的情况下，
> 仅凭**已经落到磁盘的那几行**定位到具体阶段。

## 1. 现场在哪

| 文件 | 内容 | 何时写入 |
|---|---|---|
| `%APPDATA%\smind\logs\main-YYYY-MM-DD.log` | 应用日志（含 `stage` 行，按天一个文件，超过 1MB 轮转 `.old`） | 实时 |
| `%APPDATA%\smind\diag\last-state.json` | 冻结现场转储：完整 wire（含工具参数）+ workbook + 阶段 | AI 回合内节流 2 秒，**每次写意图落地后强制**一份 |
| `%APPDATA%\smind\autosave\slot-*.xmind` | 文档自动存档（每 30 秒） | 后台定时 |
| `.tmp-check/poison-*.txt` | 内容二分器认定的「毒块」内容 | 手动跑 `npm run diag:freeze` 时 |

主进程在渲染进程卡死时还会写 `unresponsive` / `unresponsive-reload`（10 秒自救重载）两行——
它们的**时间戳**就是卡死发生的时刻。

## 2. 探针都埋在哪、长什么样

全部以 `[stage]` 开头（渲染进程 `console.log` → 主进程 console-message → 日志文件；
这条通道**在打包版同样有效**）。

```
[stage] 诊断已开启（AI 回合：12 个工具调用）
[stage] 进入 应用写意图（code）
[stage] 慢 应用写意图 180ms（code）
[stage] 进入 画布布局（节点 24）
[stage] 慢 画布布局 1400ms（节点 24）
[stage] 画布提交完成（节点 24）
[stage] 画布布局 | 应用写意图×3 代码块渲染×36 | 代码块 span 8640 · 堆 210MB   ← 每秒一行心跳
[stage] AI 回合结束：画布布局×12 共 3400ms(最慢 1400) · 应用写意图×12 共 210ms(最慢 30) · 代码块渲染×288 · 代码块 span 共 45 万
```

探针分三类，各自回答一个不同的问题：

| 探针 | 回答的问题 |
|---|---|
| `进入 X`（每个阶段**进入时立刻写**） | 「卡在哪一步」——卡住的阶段永远不会自己报完成，**最后一条就是案发现场** |
| `慢 X 123ms`（单次超过 120ms 立刻写） | 「哪些阶段是卡顿的构成单元」 |
| 每秒心跳（阶段 + 计数 + 总量） | 「哪一类循环停不下来」（数字会大到一眼可见）；总量类指标（span 数）是二次放大的证据 |
| `AI 回合结束：…` 汇总行 | 「这十几秒花在哪了」——每个阶段的次数 / 总耗时 / 最慢一次 |

## 3. 判读表（重点）

| 日志最后一条是 | 结论 | 下一步 |
|---|---|---|
| `进入 画布布局（节点 N）` | 卡在**布局计算**（含测量） | 看同行的节点数与 `last-state.json` 的内容特征；用二分器逐块复现 |
| `慢 画布布局 …ms` 之后没有「画布提交完成」 | 卡在**渲染提交（DOM）** —— 最典型的成因是「每个 token 一个 `<span>`」体量爆炸 | 查汇总行里的「代码块 span 共 N」；对照 CHANGELOG 里的元素缓存修复 |
| `进入 应用写意图（kind）` | 卡在**写 store / 解析寻址** | 看 `kind`；若是 `moveMany` 查批量移动路径 |
| `画布提交完成` 之后一片安静 | 卡在**提交之后的其它渲染**（聊天面板重渲染、大纲面板等） | 查心跳里的 `代码块渲染×N` 是否远大于写入次数 |
| 只有 `unresponsive`，连 `[stage]` 都没有 | 说明卡死发生在**探针没埋到的位置**，或诊断没开 | 确认日志里有没有「诊断已开启」；没有就是探针点不够，补点 |

## 4. 怎么复现 / 二分

1. **抓现场**：正常用应用复现一次冻结 → 立刻去看 `logs` 与 `diag/last-state.json`（强杀进程也不会丢，这是这两份文件的全部意义）。
2. **离线二分内容**：`npm run diag:freeze [xmind 路径]`（不传路径则读当前自动存档）——
   对文档里的**每个代码块**跑渲染同一套流水线（分词 / 代码块指标 / 标题寻址），
   每块一个独立进程 + 4 秒超时，不返回的就是毒块，内容会写到 `.tmp-check/poison-N.txt`。
3. **判性质**：按上一节的判读表，区分「计算卡死」与「DOM 提交卡死」——两者的修法完全不同。

## 5. 开销纪律（为什么可以一直留着）

- 日志只在**开发版**或**AI 回合进行中**（`armDiag` 被调用过）才会真的写；
  用户自己的日常编辑（敲字、拖节点）零日志、零额外开销。
- 周期定时器常驻，但未开启时立刻返回（一次布尔判断）。
- 取证转储自带自适应：单次序列化超过 25ms 就退回节流模式，不会自己变成新的卡顿来源。
