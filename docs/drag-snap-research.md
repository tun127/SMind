## 一、当时用户看到的现象

截图里，指针停在中心主题左下角外侧那一带，屏幕上**同时**出现：

| 屏幕上的东西                    | 当时代码的含义       |
| ------------------------------- | -------------------- |
| 中心主题外围的**琥珀色虚线框**  | 「接纳方＝中心主题」 |
| 挂在分支 1 左边的绿色虚线空位框 | 「排到分支 1 前面」  |
| 别处还有一个蓝色实线空位框      | 另一套落点语义       |
| 两块内容中间真正的空白          | **没有任何提示**     |

用户的原话是「我把框拉到这里了还能吸附到根节点上」。

---

## 二、真因（已更正）

原文把根因归给"根主题被允许同级插入"。复查后确认，真正的问题有三个，其中第一个是**致命缺陷**：

1. **「成为子主题」整条路径恒为 `null`（致命）**
   `resolveDrop` 里有一条刻意规则：多选拖拽禁用「成为子主题」。
   但画布调用时传的第五个参数是 `moving.ids`＝「锚点 + 它整棵子树」，**永远非空**，
   于是**只要在拖动，拖到任何主题身上都不会吸附、松手什么都不发生**。
   自检没拦住，因为用例调 `resolveDrop` 时不传第五个参数（**调用契约不一致**）。
   → 修复：抽成纯函数 `alsoDraggedOf(drag, anchor)`，画布与自检共用；补 4 条回归断言。

2. **判定模型不对：用各向同性的"距离"表达各向异性的落点窗口**
   落点窗口天生是分轴的——同级方向只有「相邻兄弟之间那条缝」那么宽，
   生长方向（新子主题会待的地方）是**一整片区域**。
   一个半径去卡两件事，必然一边太松（100px 时把远处空白也吸进来）、一边太紧（29px 时该吸的吸不到）。

3. **提示互相矛盾**：同级插入时把「接纳方父级」框起来（琥珀虚线），会被读成"要落到父级/中心主题上"。

---

## 三、最终实现（已落地）

判定的参考实现：**`wanglin2/mind-map` 的 `simple-mind-map/src/plugins/Drag.js`**。
它的核心做法是**不用"到节点的直线距离"**：先要求指针落在节点垂直于同级方向的投影内，
再沿线分三段（相邻兄弟缝隙的一半 → 插前/插后；落回本体 → 成为子节点），
全都没命中才自由摆放。

本项目据此落地为：

| #   | 改动                                                                                  | 位置                                                               |
| --- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 1   | 「分轴区域 + 就近」：区域按两条轴**分别**外扩，命中候选里取离本体最近的（同距取更深） | `shared/model/drop.ts` 的 `nearestInRegion`；画布的 `snapRegionOf` |
| 2   | 取参契约抽成纯函数（修掉上面的致命缺陷）                                              | `shared/model/dragmove.ts` 的 `alsoDraggedOf`                      |
| 3   | 非法落点给出**可读原因**（"它已经是这个主题的子主题了"/"多选拖拽只能插到同级之间"）   | `shared/model/drop.ts` 的 `blockReasonOf`；画布底部提示            |
| 4   | 同级插入**不再框父级**，只高亮参照的那个主题（琥珀 → 蓝色）                           | `TopicNode` 的 `highlight='sibling'`、`styles.css`                 |
| 5   | 落点**迟滞**：换目标前指针要先走够 14（**屏幕像素**，与缩放无关）                     | 画布 `DROP_HYSTERESIS`                                             |
| 6   | 某一层**最外侧**多留 2.4 个纵向间距，方便「追加一个子主题」                           | 画布 `OUTER_REACH`                                                 |
| 7   | 底部图例：拖拽时把「这一下会发生什么」对应的那一条点亮                                | 画布 + `styles.css`                                                |

## 四、调参入口（要改手感就改这几个常量）

| 常量                    | 值（世界单位）    | 含义                                                           | 位置                   |
| ----------------------- | ----------------- | -------------------------------------------------------------- | ---------------------- |
| `GROWTH_REACH`          | `gapX × 1.5` ≈ 84 | 沿**生长方向**（子节点那一片）的外扩量                         | `Canvas.tsx`           |
| `SIBLING_REACH`         | `gapY × 1.6` ≈ 29 | 沿**同级方向**（盖住那条缝）的外扩量；也用于背向生长的一侧     | `Canvas.tsx`           |
| `OUTER_REACH`           | `gapY × 2.4` ≈ 43 | 某一层**最外侧**（那一边没有兄弟）的外扩量                     | `Canvas.tsx`           |
| `DROP_HYSTERESIS`       | `14`              | 换落点前必须走过的距离（**屏幕像素**）                         | `Canvas.tsx`           |
| `zoneOf` 的 `edgeRatio` | `0.28`            | 节点本体内「插前 / 插后」占的比例（中段 44% 才是"成为子主题"） | `shared/model/drop.ts` |

> 画布的 `SNAP_PREFILTER` 只是"粗筛半径"，必须 ≥ 上面最大的外扩量。

## 五、仍未解决 / 有意保留

| 项                                               | 说明                                                                                                                                                     |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **保留**「上/下缘 28% 算插前/插后」              | 与 Xmind 一致，且用户明确要求保留（拖到第一个/最后一个主题的**外侧边缘**仍是插前/插后）。成熟实现是"本体内部一律算成为子主题、只有缝隙插前/后"，取舍不同 |
| 多选拖拽**只支持同级插入**                       | 一群主题挂到一个人下面解释不通；现在会给出原因提示，不再静默                                                                                             |
| 落在「已有子节点的主题的最后一个子节点**右侧**」 | 判成"成为那个子节点的子主题"（与成熟实现的列语义一致），不是"追加到父主题"                                                                               |
| 外扩量是**固定世界距离**                         | 不同结构、不同节点尺寸下的手感可能仍需微调；改上面表格里那几个常量即可                                                                                   |
| 边界 / 概要不可拖动                              | 只有关系线支持线身拖动改弯度                                                                                                                             |

### 2026-09-18：这一轮修掉的四个问题

| 问题                                                                                                                                                         | 修法                                                                                                                     | 位置                                            |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| **拖拽掉帧**——节点拖拽是唯一没有合帧的高频路径（滚轮 / 平移 / AI 写入都合帧了），高刷屏上 pointermove 能到 120~160 次/秒，每次都走一整遍裁决并重渲染整个画布 | `pointermove` 只记下最新位置，真正的计算每帧最多跑一次；松手前先把最后一格结算掉                                         | `Canvas.tsx` 的 `onMove` / `flushMove` / `onUp` |
| **每帧重复的几何计算**                                                                                                                                       | 吸附候选连各自的可吸附区域在拖拽开始时算一次（区域只依赖布局，而布局在拖拽期间是冻结的）；拖拽提示的标题不再每帧全树遍历 | `Canvas.tsx` 的 `snapCandidates` / `dragTitle`  |
| **过期的"非法落点原因"**：先撞上非法落点、再移到合法位置，底部仍挂着那条提示                                                                                 | 该变量以前只在声明处初始化，**没有每帧重置**；现在每帧清空                                                               | `Canvas.tsx` 的 `applyMove`                     |
| **有些节点怎么拖都只提示"成为子主题"**：同级方向被否决时（平衡思维导图的一级主题左右分列，兄弟坐标差不能当落点依据）`zoneOf` 收到 `null` 恒返回 `child`      | `zoneForPointer` 改为与 `snapRegionOf` 用同一套轴（`pair.stack ?? insertAxis(...)`），两处不会再给出互相矛盾的答案       | `Canvas.tsx` 的 `zoneForPointer`                |
