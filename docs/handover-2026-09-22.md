## 5. D-07 的完整真相（下一轮请从这里开始，别重走弯路）

**症状**（QA 在**叶子节点**实测，可信）：编辑态 `.topic` 的 inline width —— 空叶子 76px → ASCII 打满 20 字符仍 76px → 提交后 76px；双击已有节点同样 102→102。高度 59→144 是 CSS `height:auto` 撑的，**不是布局**。

**已排除**：草稿通道（第 2 步）无关 —— 连"已提交进文档的文字"都没让框变宽；`editingId` 指向正确；DOM 里确实有文本；`21bdc5b` 的两处修法静态复核正确。

**已知的三个入口差异**：`v0.9.0` 用 `layoutSheet(...)`（无缓存全量），现在用 `layoutSheetCached(..., [editingId])`（增量缓存）。

**本会话已修的三处**：

1. `core.ts` `measureAll`：早退条件 `isClean(topic)` → `isClean(topic) && !seeded`（seed 优先于"干净"，否则增量层塞的测量读不到）；
2. `incremental.ts` hot 循环：`!before` 时不再空手 `continue`，按 id 建「当前树」索引（含 `detachedChildren`）重量一次放进 `fresh`；
3. `incremental.ts` ⑤（refresh）分支：加编辑期守卫 `!geometryChanged && hot.size === 0` —— **`withMeasure()`（:185）设计上只换 topic 引用、不改 width/height**，编辑期落进 ⑤ 宽度就永远不变。

### ✅ 已按 §26 修（`ffae926`）—— 仅剩真机读数

修法（§26.4 第 1 条，最小且一定生效）：编辑期 override 把 `titleRich` 置为 **`undefined`**，
让 `measure` 回落到读 `title`（= 当前 live 文本）。代价：**编辑期丢失逐 run 的字号/加粗对宽度的影响**
（提交后恢复正常）——明知的取舍；若要保留，需按 live 文本重建 rich（下一轮可做）。

**下一步只剩验证**：跑 `scripts/verify/d07-accept.cjs`（测法按 §24：Range 选中 + 真 Backspace /
`data-topic-id` / 叶子节点）读出 W0/W1/W2/W3（W1 > W0+60、W2 ≈ W0、W3 ≈ W2）。
**通过 → D-07 收口**；不通过 → 读 `window.__layoutDiag`（`82fc870` 埋的四种读数含义见上）。
⚠️ **别再从缓存方向查**：`core.ts` / `incremental.ts` 那三处修法（`21bdc5b` / `82fc870`）是对的、
可以留着，但 §26 已证明它们**不是**本症状的原因。

**诊断出口（82fc870 埋好，下一轮直接用）**：`window.__layoutDiag = { pass, editingHits, editingMisses, memoRuns }`。

- `pass = 'fit'` → hot 没传进去（`incremental.ts:231-245` 的 ① 分支）；
- `pass = 'refresh'` → 锅在 `withMeasure`（已堵，若仍 refresh 说明守卫没生效）；

**测法要点（我两次没跑通的坑，§24 已列）**：清空**不要**用 `Ctrl+A`（会直接关掉编辑态，读数变 null）→ 用 `Range` 选中 + 真 `Backspace`；节点身份用 `data-topic-id`，不要按"中心点最近"；**在叶子节点上测**（根节点上限与内边距不同、会掩盖问题）。

**参考方向**：先让"编辑期测量是否生效"可观测（已做）→ 再决定最小修，或把编辑期排除在增量之外（等价 v0.9.0，已被证明可用，代价是每次输入整图重排）。

## 7. 环境坑（本会话全部真实踩过）

1. **含中文的脚本必须用文件工具写**（不要用 PowerShell 的 `Set-Content -Encoding ascii` 承载中文 —— 中文会在写脚本那一刻变成 `?`，然后被原样写进源码；门槛全绿也查不出）。脚本改写项目文件一律 `fs.writeFileSync(path, text, 'utf8')`，跑完**必须 `git diff` 扫中文**。
2. **改文件要按作用域定位，不要按"某个名字出现的地方"定位**：本会话三次把 prop 插错位置（同一个名字既有透传、又有简写传参两种出现点）。
3. **门禁要用退出码**：`.tmp-check\gates.ps1` 已改成 `BAD_GATES` 计数当退出码。曾经用正则匹配 `SUMMARY` 里的 `=> 1`，结果在 lint 失败的状态下提交过一次。
4. **跑门槛前先确认确实有改动**（`git status` 非空或说明断言数为何不变）—— 本项目三次「全绿却不正确」，其中一次就是"脚本没执行、门槛报的是没改动的绿"。**先看脚本的 `ok/MISS` 输出，再信门槛。**
5. **CRLF**：项目文件多为 CRLF，按 `\n` 拼的多行锚点会 MISS → 用"行尾无关"的正则，或**按行号定位**。
6. **`git commit -m` 的正文里别放英文双引号**（pwsh 会提前截断参数，把后半段当成 pathspec）→ 有正文就写消息文件走 `-F`。同理，提交信息**不要复用**（出现过两个同名提交）。
7. **`pwsh` 不在 PATH**（`pwsh: not recognized`）→ 用 `& '绝对路径\xxx.ps1'`，或直接 dot-source。
8. `--remote-debugging-port` 起的 App 进程**用完要自己关**（脚本只关 ws 连接，不杀进程）。
9. `.tmp-check` 会被别的会话清理 → 长期资产放 `scripts/`，临时脚本放 `.tmp-check`。
