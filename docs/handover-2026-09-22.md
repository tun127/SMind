## 5. D-07 / D-14 的完整真相（下一轮请从这里开始，别重走弯路）

### 5.1 D-07 终局根因（`core.ts` 归一化阶段的**节点对象复用**，§29）

`LayoutBuilder` 在"平移 + 归一化"那一步复用上一轮的节点对象，判据是：

```ts
const previous = this.memo?.nodes.get(node.id)
if (previous &&
    previous.topic === node.topic &&      // ← 只比 topic 引用
    previous.x === movedX && previous.y === movedY &&
    previous.depth === node.depth && previous.side === node.side) {
  this.nodes[index] = previous            // ← 整块换回旧节点，含旧 width
  continue
}
```

**编辑期工作簿根本没变** ⇒ `topic` 引用与坐标都没变 ⇒ 条件全中 ⇒ 把上一轮的节点对象整块换回来，
**刚量出来的宽度（228px）被静默丢掉**，于是框永远停在旧值（叶子 76px）。
注释里「复用必须同时看主题对象」的假设，在**「测量源在 topic 之外」（编辑期 `editingText` / 实时草稿）**时不成立。

**修法**（`9f5f57a`）：复用条件补两条 —— **尺寸必须相同**（`previous.width/height === node.width/height`）
+ **热节点（`touched` 命中）一律不复用**。

**判据链（怎么定死它的，值得记住）**：`window.__layoutDiag` 的五个实测值把范围一路缩到一格 ——

| 读数        | 取值                    | 排除了什么                              |
| ----------- | ----------------------- | --------------------------------------- |
| `memoRuns`  | 每键递增                | ❌ useMemo 没重跑                        |
| `pass`      | `incremental`           | ❌ 走了 `refresh`（`withMeasure` 不改宽高） |
| `editingHits/Misses` | `1 / 0`        | ❌ 没进 hot / 门没命中                   |
| `titleLen`  | 20（= 实时文本）        | ❌ 文本没传到                             |
| `editingWidth` | **228 而渲染框仍 76** | ✅ **测量对、布局丢** → 只剩"复用"这一格 |
| 提交后       | 228 ✓                   | ❌ store 里没文本                        |

**诊断出口（`82fc870` 埋好，现在多了五个值）**：
`window.__layoutDiag = { pass, editingHits, editingMisses, memoRuns, titleLen, draftLen, editLen, richLen, editingWidth }`

- `pass = 'fit'` → hot 没传进去（`incremental.ts` 的 ① 分支）；
- `pass = 'refresh'` → 锅在 `withMeasure`（已堵；若仍 refresh 说明守卫没生效）；
- `memoRuns` 不涨 → `use-canvas-layout` 的 useMemo 没重跑；
- `editingHits = 0` → `measure` 的门 `topic.id === editingId && editingRich` 没命中；
- **`editingWidth` ≠ 渲染框宽 → 布局把新测量丢了（就是 §29 那一处）** ← 最有用的一个。

**§26 与其它三处修法的定位（别搞混）**：
- `21bdc5b`（`measureAll` 早退加 `!seeded`；hot 循环 `!before` 时按当前树重量）、`82fc870`（refresh 守卫）、
  `ffae926`（override 的 `titleRich` 置为 `undefined`）——**都是真缺陷、都该留**，但**都不是本症状的瓶颈**；
- 其中 `ffae926` 是**必要**的：`measure.ts:232` 是 `topic.titleRich ?? richFromPlain(topic.title)`，
  只要 `titleRich` 非空，`title` 就被忽略 —— 不置空的话连"文本都读不到"。

### 5.2 D-14 根因（草稿通道挂在 rAF 上，§30）

override 读的是 `editingDraftText || editingText`（**草稿优先**），而草稿的上报挂在
`requestAnimationFrame` 上（当初为合并组词事件）。**只要那一帧的 rAF 没跑到，草稿就永久停在旧值** ——
之后无论怎么删字，`editingText` 再对也没用，因为它被草稿盖住。

实测（清空后）：`editLen=0`（store 清了 ✓）但 `draftLen=20`（草稿没清 ✗）⇒ `titleLen=20` ⇒ `editingWidth=208` ⇒ 框不缩。

**修法**（`dababc6`）：草稿改 **同步上报 + 按值去重**（值没变不写 store），触发点从 4 个扩到 6 个
（`compositionstart/update/end`、`input`、**`beforeinput`**、**`keyup`**）。

**教训**：**"为性能引入的异步合并"（rAF / throttle / debounce）是"值永久停在旧态"类缺陷的高发地**；
凡是拿它做同步的，必须配一条**最终一致的兜底**，否则丢掉的那一帧会变成永久状态。

### 5.3 测法要点（三轮白跑换来的，务必照做）

1. 清空**不要**用 `Ctrl+A`（会直接关掉编辑态）→ 用 `Range` 选中 + 真 `Backspace`；
2. 节点身份用 **`data-topic-id`**，不要按"中心点最近"（布局一动就匹配到别的节点）；
3. **在叶子节点上测**（根节点宽度上限与内边距不同、会掩盖问题）；
4. **合成输入只用于回归，不作为验收依据**：`dispatchKeyEvent + text` 会**改 DOM 但不产生 ProseMirror 事务**，
   读数会假 FAIL（§27 因此一度误判）→ 用 `Input.insertText` 或直接派发事务；
5. 每轮打字后**校验 DOM 文本长度**，不符就报"测法不可信"，不要给 FAIL 结论。

## 7. 环境坑（本会话全部真实踩过）

1. **含中文的脚本必须用文件工具写**（PowerShell 的 `Set-Content` 会把中文写成 `?` 并原样进源码，门槛查不出）。脚本改项目文件一律 `fs.writeFileSync(path, text, 'utf8')`，跑完**必须 `git diff` 扫中文**。
2. **改文件要按作用域定位**，不要按"某个名字出现的地方"定位（同一个名字常有多处出现点）。
3. **门禁要用退出码**（`.tmp-check\gates.ps1` 已改成 `BAD_GATES` 计数当退出码）。
4. **跑门槛前先确认确实有改动**（`git status` 非空或说明断言数为何不变）——本项目三次「全绿却不正确」。
5. **CRLF**：按 `\n` 拼的多行锚点会 MISS → 用行尾无关的正则或按行号定位。
6. **`git commit -m` 正文别放英文双引号**（pwsh 会提前截断参数）→ 写消息文件走 `-F`；**也别用 bash heredoc（`<<'MSG'`）**，pwsh 不支持。
7. **`pwsh` 不在 PATH** → 用 `& '绝对路径\xxx.ps1'`。
8. `--remote-debugging-port` 起的 App **用完要自己关**（脚本只关 ws，不杀进程）。
9. `.tmp-check` 会被别的会话清理 → 长期资产放 `scripts/`。
10. **数"待推条数"之前必须 `git fetch`**：拿过期的跟踪引用会多数（本项目把 20 条说成 43 条，交接文档里错了一版）。
11. **`typecheck` 与 `build` 是两回事**：本会话出现过 `build` 绿而 `typecheck` 红的改动（vite 会剥掉类型）——门禁必须包含 typecheck。
12. **`RichTextEditor.tsx` 里 `useEditor` 是 tiptap 的**：从 store 导入同名 hook 必须用别名（否则编辑器建不出来、画布全白）。
