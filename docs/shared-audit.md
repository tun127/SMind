## 2. Layering check

**Result: clean. No file under `src/shared/**` imports renderer, main, or preload — zero hits.** Verified by resolving every relative import in all 83 files (all resolve inside `src/shared/**`, `src/shared/*`) plus a literal scan for `@/`, `@shared`, `electron`, `../main`, `../../main`, `../../../renderer`: the only non-relative import in the whole subsystem is `jszip` (`xmind/serialize.ts:1`). The only `electron` hits are inside doc comments (`ipc.ts:352`, `openfile.ts:10`, `ai/errors.ts:76`, …).

**Import cycles among shared modules: exactly one, and it is type-only (erasable):**
- `layout/types.ts:2` `import type { CodeMetrics } from './accessory'` ↔ `layout/accessory.ts:9` `import type { Size } from './types'`.
  Both are `import type`, so nothing is emitted and there is no TDZ risk; but the TypeScript/ESLint cycle graph will report it, and `accessory.ts:11` re-exports the type (`export type { Size }`) which is how the cycle was introduced. All other shared files form a DAG.

**Cross-directory hub: `layout/` → `model/` (28 import edges, by far the largest), then `agent/` → `model/` (9) and `xmind/` → `model/` (9).** Nothing imports *into* `layout/` except `agent/run-read.ts:10` (`parseRange` from `'../layout'`) — an odd one-way edge from the agent tool layer into the layout layer for a pure string function that arguably belongs in `model`. `layout/` → `xmind/constants` (5) is the second notable hub.

**The facade is not the access path for the renderer.** `layout/index.ts` exports 17 names (lines 17-35), but of the 25 renderer→layout import sites only 4 go through the facade (`Canvas.tsx:10`, `store/editor.ts:59`, `export/index.ts:13`, plus `Canvas.tsx:12`→`overlays`); the rest reach straight into submodules — `@shared/layout/accessory` from 6 files (`App.tsx:33`, `NodePanel.tsx:17`, `TopicNode.tsx:20`, `export/drawing.ts:29`, `render/formula.ts:12`, `render/measure.ts:22`, `store/editor.ts:37`), `@shared/layout/types` from 8 (type-only), `@shared/layout/core` (`TopicNode.tsx:10`), `@shared/layout/label-fit` (`measure.ts:23`), `@shared/layout/overlays` (`Canvas.tsx:12`, `drawing.ts:31`). This is deliberate for a few of them (the type module *is* the contract) but it means the facade's export list understates the real dependency surface, and any reorganisation inside `layout/` breaks renderer call sites that the barrel was supposed to protect. `layout/overlays.ts` and `layout/core.ts` are only ever consumed as submodules, never through `layout/index.ts`, except for the four names re-exported at index.ts:24-34.

**IPC closure: complete. 70 channels in the `IPC` table (`ipc.ts:103-204`), 70 in main** — 66 `ipcMain.handle/on` registrations plus 4 send-only channels that main only ever *sends* (`fileOpenRequest` `ipc.ts:107` sent at `main/index.ts:1006,1072,1078`; `closeRequest` `:116` at `main:1029,2402`; `menuCommand` `:137` at `main/menu.ts:15`; `aiStreamEvent` `:166` at `main:546`), all four received in preload (`preload/index.ts:37-41,81-85,87-91,157-161`). No channel in shared lacks a main handler, and no main handler is absent from shared. `ipc-args.ts` is in sync (exports at `:19,30,41`, used at `main/index.ts:13,1218,1226,1506,1972,1985,2048,2115,2241`). One real drift — **已修（2026-09-18，`749e7d1`）**：`ipc.ts:371-382` 曾声明 `turnId` 而 `preload/index.ts` 把它窄化掉（`shared/license.ts` 因此把每轮请求都当成一个新回合计费）；现在 preload 的 `aiChatStream` 选项已带上 `turnId`。审计当时的口径是 69 条通道；`window:close-cancel` 加入后为 70 条，已用脚本逐条核对：70 条全部能在 preload 与 `main/index.ts` / `main/menu.ts` 里找到引用（无缺失）。

**One reversed dependency, by design but worth naming: the data model depends on the file-format layer for constants** — `model/tree.ts:3`, `model/factory.ts:1` import `getStructureDef`, `DEFAULT_STRUCTURE`, `TOPIC_FOLD_KEY`, `TOPIC_SIDE_KEY` from `xmind/constants`, while `xmind/parse.ts:17` imports `createId` from `model/factory`. `xmind/constants.ts` only imports `model/types` (type-only, `constants.ts:1`), so there is no cycle and no runtime hazard — but `model` is not a leaf, and `xmind/constants.ts` is a shared vocabulary module that happens to live in the `xmind` directory.

## 3. Split-quality findings

Verification method: I extracted each pre-split file from git (`git show <parent>:<path>` for the six split commits `5e4062c`, `47452d0`, `6c2f7ee`, `a7b01ec`, `7aac5fe`, `ecec2ac`) and diffed the export-name sets against the post-split facade + submodules.

**Facade completeness: all six are lossless. `LOST: (none)` for every one of them** (before→after export counts: core 24→27, overlays 16→32, graphic 3→5, agent 33→42, code 5→14, ai 59→59). No previously-public name was dropped. Newly *added* names are almost entirely internals that became public when moved to their own module (see §4).

- **`layout/core.ts` → `core/{cache,geometry,connect}.ts`** — correct and coherent. `core.ts` keeps `LayoutBuilder` and re-exports the three modules with `export * (`core.ts:40-42`). New names vs. the old file: `LayoutRuntime`/`setActiveRuntime`/`activeRuntimeOf`. Not a grab-bag: `cache.ts` is pure data/lifecycle, `geometry.ts` is 32 lines of stateless primitives, `connect.ts` is the two-phase "connect after normalization" implementation the header describes. `geometry.ts` is small but justified (it is the one module both `core.ts`'s builder and `connect.ts` depend on).
- **`layout/overlays.ts` → `overlays/{range,metrics,reserves,shapes,build}.ts`** — coherent; no grab-bag. `metrics.ts` at 17 lines is tiny but is *the* single source of the reserve/draw shared constants and is imported by two siblings (`reserves.ts:11`, `build.ts:11-21`) — justified. Note the facade deliberately re-exports only the old public surface (`overlays.ts:16-34`), so `boundsOfTopics`/`indexSubtreeBounds`/`sameBounds`/`labelRectOf`/`unionBounds`/`bracePath` and the 9 metric constants are *module-public but barrel-private*.
- **`layout/graphic.ts` → `graphic/{span,fishbone,matrix,radial}.ts`** — clean; the 11-line facade matches the plan. `span.ts` is 23 lines and is used by all three algorithms (`fishbone.ts:11`, `matrix.ts:8`, `radial.ts:9`) — justified.
- **`agent/index.ts` → 8 files + facade** — the facade is complete and the dependency graph inside the directory is acyclic and layered (`tools-read` → `address`/`run-read` → `plan-write`). Two caveats: (a) the doc header (`index.ts:3-17`) claims "no network (main), no turn loop (renderer), no write-intent landing (renderer)" — that is true; (b) `plan-write.ts` (688 lines) is the largest submodule and pulls together address resolution, outline parsing, duplicate detection, marker-group constants, and per-tool `if (name === …)` arms; it is cohesive as "the write-tool planner" but it is the one file that would benefit from a second split (`plan-write/` by tool family). `availability.ts` (85) mixes round limits, tool visibility and intent classification but is small enough that splitting would be ceremony.
- **`code/highlight.ts` → `lang-defs.ts` + `lexer.ts` + entry** — correct, and the *entry keeps the original filename* rather than becoming a bare barrel (documented at `highlight.ts:4`). This is the only split where the facade is not a pure re-export: it owns the LRU/byte-budget cache and `highlightCode`. No duplication between entry and submodules — `normalizeCodeLanguage` exists exactly once (`highlight.ts:20`), the scanners exactly once (`lexer.ts`), the tables exactly once (`lang-defs.ts`).
- **`ai/index.ts` → `ai/{config,prompts,outline,context,errors,stream}.ts`** — the only split with **zero** export-surface change and zero leftover duplication. `errors.ts` is the single mixed-responsibility file: `claimsAppliedChange` (`errors.ts:68`) is a semantic check on model text and `formatTokenCount` (`errors.ts:91`) is a number formatter — neither is "response/error copy" as the facade header (`index.ts:11`) claims. Both are unlikely to grow, so this is a naming problem more than a structural one.

**Leftover duplication between facade and submodules: none found in any of the six.** The only same-named pair anywhere in the split set is `bracePath`, and it is *two different functions*: `layout/core/connect.ts:499` (vertical brace for brace-maps, 4 args `x, yTop, yBottom, tipX`, called at `stack.ts:304`) and `layout/overlays/shapes.ts:20` (axis-parameterized brace for summaries, 6 args `axis, spanStart, spanEnd, base, spine, nib`, called twice at `build.ts:219,246`). Each has exactly one consumer and neither is a fork of the other — but the name collision across `core.ts`'s `export *` and the overlays barrel is a real ambiguity hazard if a future caller imports both.

**`export *` ambiguity:** `layout/core.ts:40-42` is the only `export *` chain in the shared layer. It re-exports `cache.ts` + `geometry.ts` + `connect.ts`, and `layout/index.ts:17` additionally does `export * from './types'`. So `@shared/layout` surfaces the union of all of them. Concretely, `Anchor` and `Point` (`core/geometry.ts:12,14`) become public names via `@shared/layout`; nothing else in the tree exports those names, so there is no collision today, but any future `Anchor`/`Point` in `layout/types.ts` would collide silently.

## 6. Correctness / logic smells, by severity

**HIGH**
1. **Floating (detached) topics cannot be detached, moved or deleted, and delete reports success anyway.** `model/tree.ts:104` `detachTopic` searches only `parent.children.findIndex` and never `parent.detachedChildren` (`model/types.ts:97`); `moveTopic` (`tree.ts:122-135`) resolves the parent the same way, so a floating topic's move silently fails. `renderer/src/store/editor.ts:1210` returns `true` from `deleteTopic` regardless of what the tree helper returned (`editor.ts:1188-1210`), so the UI claims the deletion happened. Related and mechanical: `countDescendants` (`tree.ts:322-330`) *does* count floating subtrees while `ancestorsOf:65` and `subtreeIds:93` skip them, so fold/hidden counts (`tree.ts:235-243`, `:274-283`, `:299-303`, consumed by the AI context) over-count for exactly the topics the rest of the code treats as detached.
2. **`String.fromCodePoint` unguarded → uncaught `RangeError` on hostile/odd input.** `document/index.ts:171` and `:175` guard only with `Number.isFinite(code)`; `import/markdown.ts:97` guards only with `code > 0`. Confirmed by execution: `String.fromCodePoint(1114112)` throws `RangeError`. So a docx/xlsx/pptx cell (or pasted Markdown) containing `&#1114112;` throws out of document extraction / inline parsing instead of leaving the literal. `xmind/xml.ts:31-38` already has the correct clamp — the fix is to reuse it. (Whether an outer handler catches it in `main/document.ts` I did not verify; the throw itself is certain.)
3. **Unclosed Markdown code fence silently drops the whole block.** `import/markdown.ts:565-577`: the closing branch is the only place a `code` event is emitted, and there is no flush after the `forEach`. There is no self-check for this (`scripts/selfcheck.ts:10458,10476` only cover *closed* fences). Related: the fence test is `if inFence` on *any* line matching `/^(```|~~~)/`, so `~~~` closes a ` ``` ` block and fence length is ignored.
4. **A leading `---` turns the whole document into front-matter.** `import/markdown.ts:557-564`: `index === 0 && trimmed === '---'` enters front-matter and skips every following line until another `---`/`...`. A document that merely begins with a horizontal rule imports as **empty**, with no warning. The self-check at `scripts/selfcheck.ts:10463` only exercises a *well-formed* front-matter block, so the lossy case is unpinned.

**MEDIUM**
5. **`resolveDrop` silently converts "sibling of the root" into "append as root child".** `model/drop.ts:66-79`: for `before`/`after` on the root, `findParent(root, root.id)` is null so the `zone !== 'child' && targetParent` branch is skipped and `drop.ts:79` returns `{mode:'child', parentId: targetId}` — the doc comment at `drop.ts:44-45` says that case should be illegal and return null. A drag that the user expects to be rejected becomes a reparent.
6. **Case-insensitive search and replace map indices between two different strings.** `search/index.ts:74-89` (`replaceInText`) and `:95-101` (`snippetOf`) locate the match in `text.toLowerCase()` but slice the *original* `text`. `toLowerCase()` is length-changing for some code points: verified by execution, `'\u0130x'.toLowerCase().length === 3` while `'İx'.length === 2`, so a match at index 0 yields `text.slice(0, 0) === ''` and the replacement **deletes** the `İ`. The snippet window is likewise skewed by one. Real-world frequency is low (Turkish `İ`, ligatures) but the failure is silent text corruption, and it is trivially testable.
7. **`moveTopic` lets `index: null` through the idempotence guard.** `agent/plan-write.ts:177` treats "already in that parent AND `args.index === undefined`" as a no-op, but the model's `index` is `number | null`; when the model explicitly sends `index: null` the guard is skipped, the intent is created, and the tool then reports `目标位置不合法` (the summary claims a move that never happens). Either normalize `null → undefined` before the guard or accept both.

42. `agent/plan-write.ts:119`: the copy-detection threshold counts matches against the **whole** document, so legitimately re-inserting a subtree under a different branch is refused unless `allowDuplicate: true`. Deliberate (`plan-write.ts:101-103`) and the false-positive shape is not disclosed in the refusal text.
43. `agent/plan-write.ts:135` **over-reports the node count by 1**: `parsed.count` is computed after the synthetic wrapper root is added (`ai/outline.ts:212-220`) while `plan-write.ts:98` strips that wrapper before inserting, so the summary "共 N 个节点" is wrong whenever `wrapped` is true. The `count` field has no other consumer (grep `intent.count` → 0 hits under `src/renderer`), so the damage is user/model-visible text only.
44. **`outlineRows` emits floating topics even in the panel's `skipCollapsed` mode.** `outline/index.ts:84` walks `skipCollapsed ? visible : topic.children` but `:86` then walks `topic.detachedChildren` unconditionally. The comment at `:83` scopes that mode to "visible branches only", so a floating topic is hidden on the canvas yet listed in the outline panel (and, inconsistently, exported too). Whether the panel wants them is a product question; the two lines disagree.
45. **History dedupe keeps the *first* entry, not the newest.** `history/index.ts:63-65`: the loop skips a path already in `seen`, so when an on-disk file contains two rows for one path (reachable after a crash between `recordVisit` and its write, or a hand-edited file), the older one wins on `openedAt`/`openCount`/`pinned` and the newer is discarded — even though `sortEntries:82` then sorts by recency. `recordVisit:95` itself keeps the list unique going forward, so this only bites on damaged input.
46. **Non-atomic writes for the wrong files.** `src/main/atomic-write.ts:19` exists and is used for autosave (`main/index.ts:1267`), chat history (`:1992`), diagnostics (`:2010`) and licenses (`main/license/index.ts:63`) — but **not** for the settings file (`main/index.ts:1425`), the themes file (`:388`) or the AI config (`:452`), nor for the history index (`main/history.ts:49`) or the snapshot index (`main/snapshot.ts:71`). A torn write on any of those loses a user-visible dataset (settings, custom themes, open history, the whole snapshot list), whereas the crash-recovery data is the part that is protected. The audit-facing consequence for this document: `history/index.ts`'s dedupe (item 45) and `snapshot/index.ts`'s `normalize*` fallbacks are load-bearing precisely because these files can be half-written. Ordering makes it worse in the snapshot case: `main/snapshot.ts:146-155` writes the `.xmind` *before* saving the index, and `:171-177` deletes files *before* saving the index, so an interruption leaves orphaned files (harmless) or index rows pointing at nothing.
47. **Drop geometry uses strict and non-strict comparisons interchangeably.** `model/drop.ts:303-309` (`closestNodeWithin`) tests `distance < maxDistance` while its own doc at `:290-295` describes the exclusion as "exceeds maxDistance" — an exactly-at-limit drop is rejected; `nearestSiblingGap:345` uses `<=` for the same kind of bound, and `stackDirection:118-125` returns `{axis:'x', forward:true}` for both nodes sharing a center, i.e. it invents an order from a tie. Unsure which of the three is the intended contract; they just don't agree.
48. **Drop rejection reasons don't map onto the rejection paths.** `model/drop.ts:88-99` answers `'这里不能落'` for every `zone !== 'child'` case — including *legal* sibling drops — and has no branch at all for `findParent(dragged) == null` (`:62-63`), so the message the user sees is only meaningful once a null has already been returned.
49. **`searchSheet`'s local is named `trimmed` but never trims.** `search/index.ts:162-163`. Relatedly `:139-150` reports the *number of matching labels* as the label-hit count rather than the number of occurrences, so "3 label hits" can mean three fields on one label.
50. **`history/index.ts:163`:** `relativeTime` labels any 24–48 h delta "昨天", so an entry from two calendar days ago can read as yesterday. `license.ts:115-132` validates payload fields for presence only — no `issuedAt` format check and no length caps on `holder`/`order`.
